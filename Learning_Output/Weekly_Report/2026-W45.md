## 2. 知识体系分析

- **【从「按时间累积」到「按能力缺口驱动」】**：本周最大的结构变化不是多了一讲，而是**教学对象变了**——不再是「下一讲讲什么模型」，而是「当前最强短板是什么，用实验打它」。
- **【裁判优先于内容】**：Day70 的 UCT 段和 W45 的预测比较是同一个方法论——**先有裁判（DP 精确解 / Naive 基线），再谈算法好不好**。Day70 的结论甚至是「**不要用 UCT**」，这在「每一讲都必须讲一个能赢的算法」的旧范式里是不可想象的。
- **【「复跑全绿 ≠ 结论正确」被两次印证】**：W44 的 Day61（代码对、结论错）→ W45 的 g-001（复核脚本与被测脚本共享缺陷，16/16 全绿但结论反转）。**同一个病在两处复发，说明这不是偶发，是结构性的。**
- **【证据纪律工具化】**：`evaluate.py` 抽取论文数字对比 `result.json`，把「论文写错数」从人工审阅变成机器拦截。这是全项目第一次把「诚实」写进代码。
- **【断言反模式被识别】**：「预设谁该赢」的断言等于自证。→ 断言只能检验**设计公平性**与**数据性质**（如「无泄漏：origins ≤ n−h」「GM 失效可观测」）。
- **【备课内容同步收紧】**：Day67 主动搁置归档 + 清空壳目录 + 讲数口径统一（60 讲）+ Learning_Status 改消费驱动——**第一次主动减负而非加料**。
