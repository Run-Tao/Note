### 2.2 一条**可能的新坑**：断言全部通过，但 4 个静默错误一个都没被断言拦住

README 写「**6 条断言全过**」。可是本讲修的 4 个错误，全部是「**跑得通、断言全过、结论是假的**」：

- 网格上界 420/480 太小 → 最优顶在边界，断言没报（它只查「解在界内」）；
- 场景树寻优 + 真路径计分 → 断言没报（它不比较「优化分布」与「评估分布」是否同一批）；
- K 计两次 → 断言没报（无「成本 = 各分项之和」的分解校验）；
- 首批硬编码在第 1 周、L=2 → 断言没报（**没有「到货时刻 ≥ 提前期」的时序可行性检查**）。

**这不是说断言没用，而是说：现有断言的形状是「数值合理性」，而漏的是「模型语义合理性」。** 三类可自动化的闸门，成本都很低，且**都是本讲已经手工验过的**：

| 闸门 | 查什么 | 能拦住本讲哪条 |
|---|---|---|
| ① 上界饱和检查 | 最优解是否有分量贴着参数网格上界 → 报警 | 坑 ①（网格上界卡死） |
| ② 优化/评估同分布断言 | `opt_paths is eval_paths` 或 sha256 相等 | 坑 ②（过拟合假数） |
| ③ 时序可行性断言 | ∀w: 第 w 周到货量 ≤ 前 w−L_min 周的决策累计 | 坑 ④（首批硬编码） |
| ④ 成本分解恒等式 | `total == holding + penalty + salvage + fixed`（容差 1e-6） | 坑 ③（K 计两次） |

> **建议**：把这 4 行加进 `daily/` 模板的断言区。**Day85 一次、Day86 一次，两讲连着同一个病**，昨日已说「值得写进模板而不是写进两篇踩坑记」——今天它仍然只在踩坑记里。
