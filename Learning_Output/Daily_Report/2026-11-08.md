## 三、复核：今天该改但没改的那三件事

### 3.1 🔴 昨晚 P1 未动，而且问题比昨晚说的更绕

昨晚日报给的定论是：「`load_returns()` 少了 `pct_change()`，喂进去的是 Shiller 的原始水平序列。」今天我把 `raw.csv` 逐列看了，**这个定论需要修正**：

```
date,price,dividend,earnings,rate
1871-02-01,0.0135135135,0.0000000000,0.0000000000,0.0000000000
1871-03-01,0.0244444444,0.0000000000,0.0000000000,0.0018796992
1871-06-01,-0.0082304527,...
```

- `price` 列**本身就是月度收益率**（有负值、量级 1e−2），✅ 昨晚说的「price 是水平值」不成立；
- `dividend` / `earnings` / `rate` 三列**是收益率/利率量级**（1e−2 到 1e−3），也**不是**水平序列；
- **所以「补一行 `pct_change()` 就能修好」是错的**——对这一份 CSV 加 `pct_change()` 反而会把收益率变成「收益率的变化率」，得到第三样东西。

**真正的口子在哪**：这四列在 1871 年那段是**结构性退化**的（dividend/earnings 前 ~12 个月恒为 0，rate 大量为 0），真实 Shiller 数据里 price 是价格指数、dividend 是 12 个月移动股息——**这份 GitHub 数据集已经被人预处理过，且预处理方式没有在任何地方写明**。于是：

- 报告 §1 说「月频**收益率**」→ 与数据一致 ✅
- 但 §5 把「price 年化收益率的波动 0.0135 → 0.0244 的跳变」当成相关性素材，**而这四列的统计性质完全不可比**
- META.json 只写 `"type": "real"` + 来源 URL，**没有写「已预处理成收益率」** → 复核脚本和实验脚本共享同一个未经核实的前提

**结论**：昨晚「结论 F 会反转」的判断**依然可能成立，但机制不是「少了一行 pct_change」**，而是「四条异构序列被当成同质资产」。**修复动作从「加一行」升级为「先查清数据集预处理口径，或在 `load_returns()` 里显式构造可比的回报序列 + 在 META 里写明」**。这是今天对昨晚结论的一次自我修正——顺手也证明了日报自己的复核也会踩同一类坑。
