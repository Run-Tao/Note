### ⭐ 本讲最有价值的三点

1. **"模型对 ≠ 代码对 ≠ 求解器对"，三关都得过。** 备课顺序实际踩过三个真建模坑（`k[i]` 上界误写 `cap.sum()`、变量偏移量手算错位、容量行系数写成常数 1 而不是每个站的车次数 `n_j`），修完后仍然得到 `fun=0`；直到逐列打印喂给 HiGHS 的系数确认模型无误，才敢怀疑求解器。**这条排错序列本身就是教学资产**——它说明"先怀疑自己、再怀疑工具"是对的，但"怀疑完自己还要有办法怀疑工具"更重要。
2. **贪心的纯运费 24862 元竟然低于 ILP 的 26846 元。** 因为它少送两个站（运费省了 1984 元，代价是 24000 元罚金）。**这条是本讲最容易被领导问倒的地方**，也是所有"降本"汇报里最常见的口径错误：**不在服务水平不同的方案之间直接比成本**。要么两边都允许拒单，要么两边都必须全送。
3. **"有运力 ≠ 该用运力"与"边际价值 ≠ 当前用量"这两句对偶着出现。** 河湾仓当前排 0 车，看起来是最没用的仓；但容量 +1 的边际价值它**最高（2542 元/车）**——因为它离河湾片区最近，一旦多给几车就能替下坳上、云岭的长途运输。这条把"影子价格给的是优先级清单，不是一个数"讲透了，和 Day58 的影子价格主线严丝合缝。

### 🔍 本期新发现的一个"教学点漂移"（值得记一笔）

教案与 README 都把 HiGHS 缺陷的触发条件写成：

> "scipy 1.18.1 / HiGHS 1.12.0 … 缺陷触发条件（已确认）：目标系数全为正 + 最小化 + 变量有有限 0/1 上下界 + 行约束为 `≤` 形态"

**本期独立复核后，这个归因偏强，需要打折。** 三点观察：

1. **`day59b_solver_audit.py` 的结论（C 项：改符号得 −100）是实跑确认的**，这点没问题；
2. 我在独立环境（同一 wheel、numpy 2.5.2 与 1.26.4 各一、另加 scipy 1.11.4 / 1.14.1 交叉）复跑，**该最小复现稳定复现**；
3. 但把"目标系数全为正 + 最小化 + 0/1 + `≤`"当作**完整触发条件**，无法覆盖已验证的事实——例如 `min 2x+3y s.t. x+y≤4` 同样是"全正系数 / 最小化 / 0/1 / `≤`"，却给出**正确的 0**。所以当前写法**把必要条件说成了充分条件**。

> **建议（低成本、高收益）**：把 §7.2 的措辞从"触发条件（已确认）"改为"**观测到的共同特征**"，并补一句"**不构成充分条件**；判定方式仍是 `day59c` 的独立穷举对照"。这是唯一一处会让后来读者误以为"我只要避开这个形态就安全"的地方——而真实教训恰恰相反：**你没法先验判断，所以必须事后正交复核。**

## 三、新想法 / 结构性收获

1. **"整性间隙 = 现实约束的标价"这个读法可以复用。** 29.1% 的间隙在整数规划里算大（一般 1–5% 算小），它标价的其实是**"整站不可拆单"这一条业务规则**。往后凡是遇到"要不要允许拆单/拼单/分包"的问题，间隙直接就是"允许拆单值多少钱"的上界——比讲十句定性分析有用。
2. **求解器可信度的检查清单已经成型，建议固化成模板**：① 换符号/换等价写法重解；② 小规模穷举求独立最优；③ 打印喂进求解器的矩阵，先确认自己没写错；④ 看 `res.fun` 与 `c·x` 是否**一致地错**（一致 ≠ 正确）。这四条对 LP/ILP/MILP 通用，值得抽成 `08 - Python` 下的公共小工具。
3. **验收动作要和产物解耦。** 上期 P3（复跑即把 json 计时字段改脏）本期没有复发，原因是 Day59 的脚本根本不记录运行时间。这提示一个更普遍的规矩：**要复跑验证的产物里，不要放易变字段**——要么分离到 `*_runtime.json`，要么干脆不落盘。
