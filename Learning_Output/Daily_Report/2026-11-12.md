## 二、今晚实际发生了什么

### 2.1 ✅ 23:23–23:25 — Day74 重做，且是**换题**而不是**补题**

新脚本 `day74_submodular_rain_gauge.py`（19,075 B）替代了崩溃的 `day74_submodular_sensor.py`。二者的差别不只是文件名：

| | 昨天（`_sensor.py`） | 今天（`_rain_gauge.py`） |
| --- | --- | --- |
| 主约束 | 固定 K=3 + 公平约束 | **固定 K → 预算 B** |
| 核心教学点 | 「公平约束的代价」 | 「换约束就换算法，保证还成立但会崩」 |
| 公平约束 | 非紧，断言永不成立 | **整段删除** |
| 实跑 | ❌ 崩在 line 349 | ✅ **1.27 s，8 断言全过，`-W error` 零告警** |
| 交付物 | 1/5 | **5/5** |

**这正是昨天日报 §3.1 建议的反面操作 —— 而且是对的。** 昨天的建议是「把 `K_BUDGET` 降到 2 或扩 `FAIR_TARGETS` 让约束 binding」。今晚的做法更彻底：**放弃那个教学点。** 因为即使把参数调到 binding，讲的也只是「一个非紧约束变紧之后值变小」，远不如「同一个次模结构，K 换成预算，贪心从 100% 掉到 75.4%」干净有力。

**我亲自复核了结果（`.venv` + `-W error` 实跑）：**

```
固定 K=1..4：贪心 = 精确（29.90 / 52.00 / 69.55 / 78.13），ratio 全 1.000
预算 B=36：精确 [丁站,丙站] 39.650 ｜ 增益贪心 [甲站] 29.900（75.4%）
           性价比贪心 [丙站,丁站] 39.650（100%）｜ 局部搜索 [甲站] 0 次移动
次模性抽样 2731 对，破坏 0 次
耗时 1.27s
```

**有一处数字需要更正昨天的判断**：昨天说「拿 ratio=1.0 的实例讲『差距有多大』是无效教学」。今晚的处理是**把这个事实本身变成了结论** —— 「(1−1/e) 只是下界，不是损失；固定 K 覆盖结构下贪心四次全部命中最优；真正会崩的是预算版」。这比硬造一个「贪心差 30%」的例子诚实得多，也更有教学价值。**昨天 README 第 1 条避坑就是「不要为了讲 (1−1/e) 硬造例子」，今晚他听进去了。**

**一处小瑕疵**：旧的 `day74_submodular_sensor.py`（458 行）**和新脚本一起被提交进了 `ed874e7`**，而不是删除。README「废弃文件」段说保留作反面教材 —— 这个决定可以接受，但必须确保它永远不会被 cron 捡起来跑（它仍会在 line 349 崩溃）。**建议**：给这类废弃脚本加 `_discard_` 前缀，或移到 `08 - Python/_discard/`，让「文件名即状态」。

## 三、今日判断

### 3.1 ✅ 今天最值得记的：修 bug 的正确方式是「换掉错的结论」，不是「凿实例去凑结论」

昨天日报 §3.1 给了两条路：调实例参数，或放弃教学点。**今晚选了后者，并因此得到了更好的一讲。** 对比一下：

- **Day73 的失败**：参数落在可行域外，$g\equiv0$，断言太松，**沉默通过画出全 0 图**；
- **Day74 昨天的失败**：断言写对了，抓住了问题，但**问题在实例设计**；
- **Day74 今天的成功**：不是把实例凿到能通过断言，而是**换了一个断言更值得通过的实例**。

**三天，同一个作者，三种处理。第三种是对的。** 这个模式值得写进 `AGENTS.md` 或 `Teaching_Plan.md` 的「备课纪律」：**当一个教学点的断言写不出来时，先怀疑教学点，再怀疑实例，最后才怀疑代码。**

### 3.2 ⚠️ 「66:1」这个数字已经写进 MOC，但它还没有任何护栏

MOC 现在诚实地写着「产出:消费 ≈ 66:1」。这是好事 —— **但一个写明的失衡，如果没有对应的动作，等于把问题修辞化了。**

系统里现在没有任何东西会因为「消费连续 N 周为 0」而报警，而 **healthcheck 会为「磁盘 42.3%」报警**。这是一个非常清楚的优先级错配：**磁盘满不是风险，仓库自娱自乐才是。**

**建议（20 分钟级）**：在 healthcheck 里加一条 —— `如果 Inbox 连续 14 天无新增文件 → warnings 加一条 "consumption_stalled: 产出:消费 = N:1"`。它会在 06:00 自动出现在 JSON 里，然后任何读到它的人（包括明天的我）都无法忽略。

### 3.3 🔴 回执：这一项该停止「每天复述」了

这是第 5 周。昨天日报原话：「要么建，要么正式决定不建。如果不建，就别再在日报里把『0 回执』当成问题项写 —— 那只是把同一句话抄了 4 遍。」

**今天是第 5 遍。** 我不再把它列为一号建议，但**它仍然值得每天占一行**，因为它是唯一能衡量「这台机器到底有没有在帮到人」的指标。**只有当这个指标真的挂了告警（§3.2），日报才可以停止复述它。**
