### 3.3 🔴 新发现：`run_pipeline` 的失败归因会串实验（第 1 天，但会复发）

见 §2.2。核心是 `run_pipeline.py` 的两个设计缺陷：

```python
for r in todo:                                    # ← 遍历所有 approved
    rc = subprocess.run([...], ...).returncode
    r["status"] = "done" if rc == 0 else "failed" # ← 但 rc 是 subprocess 的
    rc_all |= rc
```

**`subprocess.run(...).returncode` 在 `run_task.py` 内部失败时，`run_task.py` 自己也可能返回 0**（它写了 `state=failed` 到 ledger 但仍正常退出），于是 `r["status"]` 拿到的是 **`subprocess` 是否崩了**，而不是 **实验是否通过**。**这是「用一个进程的退出码代表一个实验的科学结论」的经典错误** —— 和 11-08 日报 §3.1 批评的「脚本全绿不代表结论对」是**同一个病，同一个仓库，隔一天再次出现。**

**处方（4 行）：** `run_pipeline.py` 里把 `r["status"]` 改成从 `run_task.py` 落盘的结果读，而不是从 returncode 推：

```python
res = json.loads((ROOT/"experiments"/d/"result.json").read_text())
r["status"] = "done" if res.get("verdict") == "verified" else "failed"
```

并且 **06:10 这次的 `pending.yaml` 修改必须人工回滚**（g-001 → `approved`，或直接 `done`），因为它是错的。
