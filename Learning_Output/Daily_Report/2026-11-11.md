### 2.1 🔴 00:21 — Day74 脚本落地，但**跑不通**

`Mathematical_Modeling/08 - Python/daily/2026-11-11/day74_submodular_sensor.py`，19,810 字节，未跟踪。

**主题选得很好。** 教案头部自述的补位逻辑是准确的：Day60 只数「被覆盖点数」（边际递减天然，贪心对不对没人追问）、Day71 后悔准则选址、Day73 参数规划（预算当参数）—— 而「**目标函数本身就是集合函数**」这一族确实是库里的零命中。四个决策问题也问在了点子上：

1. 雨量站只能预警**它下游**的人（提前量 = 距离 / 洪峰流速）→ 站在下游或离太近都是废站；
2. 贪心 vs 最优差多少，与 $(1-1/e)=63.2\%$ 的理论保证并排看；
3. 加「每个村都得有人管」的公平约束后，保证还在、差距变大 —— 变大多少、贵多少；
4. 站越密，「覆盖两次」越像重复建设 —— 站间雨量相关 $\rho$ 一高，第二重覆盖同步失效。

**我实跑了。30 秒内崩溃：**

```
File ".../day74_submodular_sensor.py", line 349, in <module>
    assert S_EF is not None and V_EF > V_GF, "公平约束下贪心同样劣于精确"
AssertionError: 公平约束下贪心同样劣于精确
```

**根因不是笔误，是这一讲的教案本身没想清楚。** 我把求解段单独抽出来跑了三次数，结论如下：

| 量 | 值 |
| --- | --- |
| `K_BUDGET` | **3** |
| 主问题 精确最优 | `[0, 4, 7]` = 上坪北 / 云岭北 / 河湾北，$V_E$ = **9.3000** |
| 主问题贪心 | 同上，$V_G$ = **9.3000**（ratio = 1.0000） |
| **主问题最优解的层数** | `[1,1,0,1,1,1,1,0]` → **已经满足公平约束** |
| 公平 精确最优 | `[0, 4, 7]`，$V_{EF}$ = **9.3000** |
| 公平 贪心 | `[0, 4, 7]`，$V_{GF}$ = **9.3000** |
| 公平最优 vs 主最优 值差 | **0.0000** |

**即：K=3 时，公平约束是非紧的（non-binding）。** 不加约束的最优解本来就给上游三个村各配了站，所以：

- `V_EF > V_GF` 断言**永远不可能成立**（两者同解）；
- 顺带地，第 351 行 `V_EF < V_E`（公平约束必须付出代价）**同样永远不可能成立** —— 这条断言只是排在后面还没执行到而已。
- `V_G / V_E = 1.0`，意味着 §2 那个「贪心 vs 最优差多少」的教学点**本身也是空转的**：这个实例上贪心一次命中最优，讲不出任何差距。而 `(1-1/e)` 保证是**下界**，`ratio=1.0` 虽不自相矛盾，但**拿一个「差距为 0」的实例去讲「差距有多大」，是无效教学**。

**也就是说：整篇脚本的 3 个核心教学点（差距、CELF、公平的价格）里，有 2 个在当前参数下无定义，第 3 个恒为零。** 不是修一行的问题，是**实例参数没调到让结论成立的位置**。

> [!note] 这不是第一次
> Day73 的 README 自己写过第 2 条避坑：**「第二版基数 38 落在可行域外，$g\equiv0$，脚本沉默通过，画出一张漂亮的全 0 图」** —— 那次是「断言太松，假象通过」。今天是反面：**断言写对了，抓到了问题，但问题出在实例设计，不是代码。**
