# Day24 · 稳定婚配（Stable Marriage）与 Gale-Shapley 延迟接受算法

> 代码：[[2026-09-24/README|08 - Python/daily/2026-09-24]]；脚本 `stable_marriage_gale_shapley.py`；图 `stable_marriage_gale_shapley.png`。
> 前置：[[Day22 - 指派问题匈牙利算法与二分图匹配]]、[[Day23 - 运输问题最小费用流与西北角Vogel法]]。

## 一、这道题在问什么

4 位男士 M1–M4、4 位女士 W1–W4 要**两两配对**。每个人心里对异性的喜好排序（越靠前越喜欢）：

| 男士 | 偏好（最喜欢→最不喜欢） |
|---|---|
| M1 | W1, W2, W3, W4 |
| M2 | W2, W1, W3, W4 |
| M3 | W3, W2, W1, W4 |
| M4 | W1, W3, W2, W4 |

| 女士 | 偏好 |
|---|---|
| W1 | M2, M1, M4, M3 |
| W2 | M1, M3, M2, M4 |
| W3 | M3, M2, M4, M1 |
| W4 | M4, M3, M1, M2 |

问：怎样配对，才能让**谁都不想"私奔"**？

这里没有"总幸福分最高"这种明确目标——**理想目标其实无法定义**（每个人偏好不同，无法加总成公认的一把尺）。真正可行的目标是**稳定性**：不存在一对男女，双方都更愿意跟对方在一起而不是自己当前的伴侣。

## 二、关键概念：什么是"不稳定"

给定一个匹配，若存在一对 $(m, w)$ **当前不是夫妻**，但：
- $m$ 更喜欢 $w$ 胜过他现任，
- $w$ 也更喜欢 $m$ 胜过她现任，

则这对叫**阻塞对（blocking pair）**——他们会双双出轨、私奔。**没有阻塞对的匹配 = 稳定匹配**。

注意"稳定"不是"每个人娶到自己最爱的人"（那几乎不可能达成）。它只保证：**没人有动机单方面破坏现状**。

## 三、10 问逐条回答

### 1. 解决什么问题？
在**双方都有偏好、且无全局可加总目标**的配对场景里，找一个无人想反悔的**稳定匹配**。典型场景：医学院毕业生 ↔ 医院（美国住院医师匹配 NRMP，实际即用此算法）、学生 ↔ 学校、器官捐献配对、室友分配、相亲/交友平台。

### 2. 什么情况下使用？
- 有两组要**一一配对**的个体；
- 每人对异性有**完整偏好排序**；
- 没有一个"总幸福/总收益"能公平加总（否则该用 Day22 的指派）；
- 目标是**稳定性 / 无人反悔**，而非单指标最优。

### 3. 为什么适合？（模型结构）
这是**二分图上的匹配问题**，但有偏好和稳定性要求——属于**匹配博弈（Matching Markets）**。与 Day22 指派问题的本质差别：

| | Day22 指派 | Day24 稳定婚配 |
|---|---|---|
| 目标 | 总成本**最小**（一个数） | **无阻塞对**（一种性质） |
| 目标函数 | 有 | **无** |
| 算法 | 匈牙利 O(n³) | **Gale-Shapley**（延迟接受） |
| 解 | 通常唯一最优 | 可能有**多个**稳定解 |

### 4. 变量 / 参数 / 目标 / 约束
- **参数**：每人的完整偏好排序；
- **决策**：一个一一映射（匹配）；
- **目标**：无阻塞对；
- **约束**：一一配对（每人至多一个伴侣）。

### 5. 怎么求解？Gale-Shapley 延迟接受算法
核心思想：**让一方不断"追求"，另一方"暂定接受、随时可反悔"**。

```
主动方 = 男士
free = 所有男士
循环直到 free 为空：
    取一个自由男士 m
    m 按偏好顺序，向还没追过的女士 w 表白：
        若 w 单身          → 暂定接受 m
        若 w 更喜欢 m 超过她现在的暂定对象 → 踹掉旧的，暂定 m（旧对象重回 free）
        否则                → 拒绝 m，m 继续追下一个
```

关键在"**延迟接受**"：女士不是一被追就定终身，而是**先握着，等更好的人来了再换**——这才保证了稳定性。

### 6. 为什么贪心/直接配对会错？
"每个人都去抢自己第一志愿"必然撞车且产生大量阻塞对。"按介绍顺序配"没有道理，结果既不稳定也不公平。**必须靠延迟接受机制**让信息逐步披露、好搭配浮出水面。

### 7. 现实变体怎么改模型？
- **数量不等**：加虚拟人补齐（同 Day23 虚设行列思路）；
- **偏好不完整/有禁忌**：从偏好表中删掉不可接受者；
- **医院招多人（多对一）**：升级为 **Gale-Shapley 医院-住院医师版**；
- **带"平级"偏好**：需要打破平级的规则（否则稳定性判据变形）。

### 8. 怎么验证结果对？
- **稳定性检验**：遍历所有非夫妻对，确认无阻塞对（本例两种主动方向都通过）；
- **穷举对照**：小规模枚举全部 $n!$ 个匹配，筛出所有稳定解（本例恰好 **2 个**）；
- **定理核对**：主动方是否拿到最优稳定匹配（见下）。

### 9. 三条著名定理（本课全部实测）
**① 算法必然终止且结果稳定。** 每次表白使某男士的"已追下标"前进，总次数有限（≤ n²），故必终止；终止时的匹配必无阻塞对。

**② 主动方得最优、被动方得最差。** 在所有稳定匹配中，**主动追求的一方**得到对他们集体最有利的那个（每人排名之和最小）；被动方则得到对他们最差的。

本例实测：男士主动 → 男士总排名和 **3**（= 全部稳定匹配中最小）；女士主动 → 女士总排名和 **0**（最小）。**"谁主动谁占优"是数学定理，不是巧合。**

**③ 结构性约束**（对某男可接受、对某女也可接受的配对，在任何稳定匹配中都成立）。实测：每位男士在"男士主动"下的伴侣排名，**永远不差于**"女士主动"下的排名。

### 10. 交付物是什么？
**一张"配对表" + 稳定性证明 + （若存在多个稳定解）解集说明**。由于稳定解可能不止一个，论文必须交代"用了哪一方的主动版本、为什么"——这是一个**显式的立场选择**。

## 四、关键结果（仓库 `.venv` 实跑）

**男士主动：**

| 配对 | 男满意度 | 女满意度 |
|---|---|---|
| M1–W1 | 第1 | 第2 |
| M2–W2 | 第1 | 第3 |
| M3–W3 | 第1 | 第1 |
| M4–W4 | 第4 | 第1 |

男士总排名和 = **3**，女士总排名和 = **3**。

**女士主动**（对照）：M1–W2、M2–W1、M3–W3、M4–W4 → 男士总排名和 **5**、女士总排名和 **0**。

**全部稳定匹配恰好 2 个**（穷举验证）：
1. M1–W1、M2–W2、M3–W3、M4–W4（→ 男士主动结果）
2. M1–W2、M2–W1、M3–W3、M4–W4（→ 女士主动结果）

**定理验证全过**：① 都稳定；② 主动方各拿最优（男 3 / 女 0）；③ 男士排名"男士主动 ≤ 女士主动"逐人成立。

**敏感性**：随机扰动偏好 2000 次，**95.8% 的结果与基准不同**——匹配对偏好高度敏感，结论必须配稳定性证明才有意义。

## 五、要点提炼

- **稳定婚配补的是"没有可加总目标"的配对场景**：Day22 指派有明确成本函数、解唯一；这里没有目标函数、解**可能多个**，目标是"无人反悔"；
- **Gale-Shapley = 延迟接受**：主动方不断表白、被动方握着可反悔，终结于稳定匹配；
- **主动方占优是定理**：谁追谁占便宜，被动方只能拿"最差稳定解"——所以现实里（如 NRMP）"谁主动"是制度设计的关键；
- **交付物含立场**：多解时须说明采用哪方主动，这不是技术细节而是**公平性选择**；
- 与 Day22、Day23 合起来，**二分图匹配家族**（指派/运输/稳定婚配）成体系：一个求最省、一个求最稳、一个求最省地搬货。

## 六、常见问题

> [!question] 稳定匹配一定存在吗？唯一吗？
> **一定存在**（Gale-Shapley 保证），但**不一定唯一**（本例 2 个）。存在多个时，主动方拿对其最优的那个。

> [!question] 为什么主动方占优反而是坏事？
> 因为它意味着**结果偏向主动方的利益**。这正是 NRMP 等制度要对"谁当主动方"反复权衡的原因——算法中立，但"谁追谁"是价值判断。

> [!question] 这和 Day22 指派能互相转换吗？
> 可以强行转（把偏好变成成本再跑匈牙利），但那样会**丢掉"稳定性"**：指派只保总成本最小，可能留下阻塞对。目标不同就别硬套。
