## 一、这一课解决什么决策

前四讲我们把「配对 / 匹配」这条线讲透了：二分图基数（Day22）、一般图基数（Day39/带花树）、二分图加权（Day40/KM）。
现在把匹配**用到一件真实得不能再真实的调度任务上**：

> **某社区环卫车要从车场出发，扫过片区里每一条街道至少一次（马路都要扫到），
> 最后回到车场，怎样安排巡游路线，总行驶里程最短？**

这就是运筹学里著名的**中国邮递员问题（Chinese Postman Problem, CPP）**——1960 年由**管梅谷**提出，
比欧拉的「一笔画」问题多了一层**权重与优化**：**每条街至少要扫一次，允许重复走，但总里程要最省**。

**决策变量**：一条闭合巡游（closed walk）$W$；
**目标**：$\min\ \sum_{e\in W} w_e$（$W$ 里每条被走的边计一次里程）；
**约束**：$W$ 经过图中每一条边至少一次，且首尾相接、连通。

## 二、先看清楚「难点到底在哪」

新手第一反应是「DFS 走一遍、遇到死胡同原路返回不就行了」——代码里专门做了这个**贪心对照**，
它给出一个**看起来合理、其实绕了冤路**的方案（本例比最优多走 7 公里）。

要理解为什么难，得先回忆**欧拉（Euler）**的结论：

- **一个连通图能「一笔画」（走遍每条边恰好一次回到起点，即存在欧拉回路）的充要条件，是每个顶点的度数都是偶数。**
- 度数为什么关键？每走进一个路口就得再走出一次，**奇度路口**意味着「进多出少」，必然有进无出、卡在那里。

于是问题自然地一分为二：

1. **若所有路口度数都是偶数** → 图本身就有欧拉回路 → 每条街各走一次，**答案 = 全部边权和**，直接收工。
2. **若有奇度路口** → 一笔画走不通，**必须把某些街重复走**，把奇变偶。

**关键建模判断：重复走哪些街，等价于「把奇度路口两两配对，沿配对之间的最短路重复走」。**
这一下就把「路线规划」翻译成了我们上几讲刚学会的**最小权完美匹配**！

## 三、为什么「把奇度点配对」就够了（10 问之 3、4）

设奇度路口集合为 $O=\{v_1,\dots,v_{2k}\}$（奇度点必为偶数个，因为度数总和是边数的两倍、必为偶）。

- 想要图变欧拉，就要让每个奇度点的度数**再加奇数**、偶度维持偶数 → **等价于在原图上叠加一个「重复边」的子集 $D$，使 $D$ 里每个奇度点恰好接奇数条重复边**。
- 一个经典结论：**这等价于把 $O$ 两两配对，配对的每对之间沿最短路径各重复走一遍。** 因为最短路就是最省的「补奇」方式。

于是问题坍缩成：**在 $2k$ 个奇度点上，用两两配对把它们连起来（配对代价 = 两点间最短路长度），
使总的配代价最小。** 这正是：

$$
\min_{\text{完美匹配 } M}\ \sum_{(i,j)\in M} d(v_i,v_j),
$$

其中 $d(\cdot,\cdot)$ 是**全源最短路**（Floyd–Warshall 算）。**这个「最小权完美匹配」就是 Day40 的 KM 算法（在取负/最小化语言下）能秒解的问题。**

> **一句话总览：** CPP 的解法 = **① 各边先各走一次（`base`）+ ② 用 FloyWarshall 求奇度点两两最短路 + ③ KM 求最小权完美匹配（选最省的配对）+ ④ 把匹配对之间的最短路加进图 + ⑤ Hierholzer 求欧拉回路，还原成一条真实巡游。**

## 四、求解与验证（10 问之 6、7）

代码（`08 - Python/daily/2026-10-10/chinese_postman_matching_euler.py`）**零专用图论库（未用 networkx）**，全部手写：

- **Floyd–Warshall** 全源最短路（含 `next` 矩阵还原路径）；
- **KM 算法（最小化版）** 求奇度点的最小权完美匹配；
  > ⚠️ 踩坑：标准 e-maxx KM 有「对角线 = 0 → 每人配自己」的假解，必须**把对角线抬成大数禁止自配对**。
- **Hierholzer 算法**在「原图 + 重复边」构成的多重图上求欧拉回路，还原成一条真实巡游；
- **`itertools` 暴力枚举奇度点的全部配对**作**独立裁判**；
- **两个对照**：A. 每条街往返两遍（笨办法上界）；B. 最近邻贪心巡游（每次都抢最近的未走街）。

**本例实际跑通结果**（社区网格：9 个路口、15 条街、总里程 65）：

| 顶点 | 度数 | 奇度？ |
|---|---|---|
| 0(车场) | 3 | ✅ |
| 1 | 4 | |
| 2 | 4 | |
| 3 | 3 | ✅ |
| 4 | 3 | ✅ |
| 5 | 4 | |
| 6 | 3 | ✅ |
| 7 | 3 | ✅ |
| 8 | 3 | ✅ |

- 奇度点 $O=\{0,3,4,6,7,8\}$（6 个）；**各走一次 base = 65**；
- **匹配后需重复走的边**：`(0,3)`、`(4,7)`、`(6,8)`（即配对 $0\!-\!3,\ 4\!-\!7,\ 6\!-\!8$）；
- **重复里程 = 10**（4 + 4 + 2）；**最优总里程 = 75**（= 65 + 10）；
- **⭐ 独立裁判**：暴力枚举全部配对 = **10**，与 KM 完全一致（KM == 暴力）；
- **⭐ 贪心对照**：最近邻巡游 = **82**（比最优多 7，+9.3%）——只顾眼前抢最近的街，最后被迫绕远回头；
- **⭐ 笨办法对照**：每条街往返两遍 = **130**（比最优多 55，+73.3%）；
- 欧拉回路序列 `[0,3,6,8,1,4,7,8,6,5,7,4,5,2,3,0,2,1,0]`：**核验覆盖全部 15 条街、且首尾闭合**。

断言全过：**KM == 暴力裁判**、巡游覆盖所有边且闭合、最优不劣于两个对照、回路段数 ≥ 边数。

## 五、结果怎么读（10 问之 8、9、10）

- **交付物不是「最优路线长什么样」，而是一份能落地的调度方案**：一条**覆盖全部街道、总里程最短**的巡游路线，
  外加**「贪心/笨办法会多跑多少」的量化证据**（本例贪心多 9.3%、笨办法多 73.3%）。
- **奇度路口就是「成本洼地」**：它们的存在强迫你重复走路，**配对费用 = 你为「补奇」付出的最少代价**。
  哪个路口是奇度、和谁配对，决定了多跑的那几公里花在哪儿。
- **敏感性视角**：如果某条街里程变了，最短路会变，奇度配对也可能**重新洗牌**——最优路线不是拍脑袋定的，是算出来的。
- **迁移面极广**：环卫/除雪/邮递/送奶/校车路线、电网巡检、街道路面检测、扫雪车、无人机巡线……
  **凡「每条边都要覆盖一遍、可重复、要最省」皆是 CPP**。这也是**「路径规划」类赛题**（如送货、巡检、覆盖）
  的常考内核。

## 六、避坑记录（写进 README 供后续复用）

1. **KM 标准实现的「对角线陷阱」**：e-maxx 最小化 KM 要求「任意行能配任意列」，
   而当代价矩阵对角线为 0（自己配自己代价 0）时会退化成「人人配自己、总代价 0」的**假解**；
   **必须把对角线抬成大数**（如 `max*(n+1)+1`）禁止自配对，才是真正的「完美匹配」。
2. **KM 求总权重要「每对只算一次」**：`match[i]=j` 是双向的，对 `i` 求和会**双倍计数**；
   必须 `sum(cost[i][match[i]] for i if i<match[i])`。
3. **Hierholzer 必须作用在「含重复边的多重图」上**：只在原图（4/6 个奇度点）上跑欧拉回路**根本不存在**——
   第一版直接对原图调用，结果回路既没覆盖全部边、也不闭合。**先补重复边、再求欧拉回路**是硬顺序。
4. **教学实例必须让贪心真吃亏**：第一版实例贪心恰等于最优，「贪心会亏」这个教学点直接落空；
   重新设计权重（在贪心必经之路上埋伏一条「很诱人但会锁死后续」的边）后，贪心多走 9.3%，教学点才立起来。
   （**教学数据要刻意设计以暴露算法行为**，与 Day22/24/25/26/31/33/34/35/36/37/38/39/40 同一教训，已第 N 次复现。）
5. **独立裁判要真独立**：`itertools` 暴力枚举全部配对（6 个奇度点 = 15 种配对）与 KM 交叉验证。
6. **图输出路径用 `__file__` 锚定**，从任意 cwd 运行都能正确落图（参照 Day36–40）。
