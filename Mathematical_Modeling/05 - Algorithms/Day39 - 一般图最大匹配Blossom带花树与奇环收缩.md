## 一、这一课解决什么决策

前几讲的「配对」都很舒服：**指派问题**里顾问和项目天然分成两拨（人 / 事），
**稳定婚配**里男和女天然分成两拨。这类图是**二分图**——点能染成两种颜色、每条边都跨色，
于是匈牙利算法、König 定理、Gale-Shapley 都能顺着「左—右」结构流畅推下去。

**但现实里的配对，常常没有这种天然的二分结构。** 今天用一个真实决策把它说清楚：

> **某三甲医院护理部要把 12 名护士两两配成「同班搭档」（1 人只能搭 1 个），
> 尽可能让大家都配上。**护士来自不同科室、不同资历，谁能和谁搭班取决于历史协作里
> 「互相认可」的关系。这层关系图**不是二分图**——因为存在**三人互相都认可**的小圈子
> （ICU 的 A、急诊的 B、ICU 的 C 三人两两愿意搭班），这就是一个**奇环**。

一旦图里有奇环，前面那套「把点分成左右两半、沿交错路增广」的推理就会**自相矛盾**：

- 二分图的增广路搜索之所以能简单实现，是因为「左右」把点强行分了层，
  搜索树上**同层点之间不会有边**。奇环恰恰打破这一点——环上必有两个点「同侧却相连」；
- 硬把非二分图当二分图跑匈牙利（本课代码里做了对照），会**丢掉最优解**：
  本例中硬套匈牙利只配出 5 对，而真正的最优是 6 对（全员配齐）。

所以今天要补上一般图匹配的**正宗武器**——**Edmonds 带花树算法（Blossom Algorithm）**，
它回答建模者最关心的四个递进问题：

> "**为什么指向同一个『配对』问题，二分图有漂亮算法、一般图却难得多？**"
> "**奇环到底坏在哪一步？——为什么不能像二分图那样简单地增广？**"
> "**『花（blossom）』是什么、把奇环收缩掉凭什么不损失最优性？**"
> "**缩进去的花最后怎么展开，才能真的把 6 对搭班还原出来？**"

## 二、从决策到模型（10 问之 1、2）

把护士当点 $V$，把「两人可搭班」当无向边 $E$，得到一张**无向图** $G=(V,E)$。

**决策变量**：$x_{uv}\in\{0,1\}$ 表示 $u,v$ 是否搭成一对。

**模型（最大基数匹配 Maximum Cardinality Matching）**：

$$
\max\ \sum_{(u,v)\in E} x_{uv}
\quad\text{s.t.}\quad
\sum_{v:\ (u,v)\in E} x_{uv}\ \le\ 1\quad \forall u\in V,
\qquad x_{uv}\in\{0,1\}.
$$

**「每个护士最多搭 1 人」这条约束，就是把问题变成「匹配」的那条约束。**
目标要让**配上的人数尽量多**（$\sum x$ 最大 = 配对数最大）。

> [!note] 为什么不直接交给 ILP 求解器？
> 这条 0-1 模型是标准 ILP，`scipy.milp` 当然能解小规模实例。
> 但**匹配问题是少有的「有多项式时间精确算法」的组合优化问题**，
> 而且 Edmonds 的带花树是理解**整个匹配/拟阵/多面体理论**的钥匙——
> 它是历史上第一个证明「一般图匹配属 P 类」的算法（1965，Edmonds），
> 直接催生了「多项式时间算法」这门学问。**学它，学的是「结构比蛮力重要」这件事。**

## 三、为什么难：二分图 ≠ 一般图（10 问之 3）

**二分图的最大匹配**（Day25）为什么简单？因为它给了我们一个**天然的「方向」**：

1. 从左侧一个未匹配点出发，交替走「未匹配边 → 匹配边 → 未匹配边……」；
2. 只要找到一条**两端都是未匹配点**的**增广路**，翻转这条路上的匹配，配对数就 +1；
3. 反复找增广路直到找不到——**Berge 定理**保证那时就是最大匹配。

关键在于第 2 步的搜索**总能保持「左点层 / 右点层」的清晰分层**，
所以只需一个简单的 BFS/DFS 就能找到增广路。

**一般图把这个分层打碎了。** 考虑最小的奇环——三角形 A-B-C（三人互相认可）：

```
    A
   / \
  B---C
```

- 若从 A 出发搜索，B 和 C 都会被「染成」距 A 为 1 的一层——**B、C 同层却有边相连**；
- 这条「同层边」在二分图里**永不存在**，于是搜索逻辑要额外处理：**这就是奇环**；
- 更麻烦的是，一旦 A 已匹配、B 未匹配，想通过奇环把 B 也配上，
  增广路会在环上「绕圈」——单纯标记「已访问」会把这个有用的环**误当死路剪掉**。

**结论**：一般图匹配的难点**不在目标函数、不在约束，而在「搜索增广路」这一步的结构**。
这正是第 4 问要解决的。

## 四、带花树（Blossom）：把奇环「收缩成花」

Edmonds 的天才之处是：**别跟奇环硬碰硬，把它收缩（contract）成一个「超级点」，
问题就退化成一张更小的图；在缩图上继续找增广路，找到后再把「花」展开还原。**

一个奇环为什么能收缩？因为它有一个漂亮的**奇偶性质**：

> **在长度为奇数的环上，从环外任意点进入环，都能以「匹配/未匹配交替」的方式
> 走到环上任意一个点。** 换句话说，环上奇数个点让「进入环后处在匹配边还是未匹配边」
> 这件事可以**由我们自主选择**。于是从「能不能接上一条增广路」的角度看，
> **整个奇环等价于一个点**——它就是一朵「花（blossom）」，环本身是「花瓣」，
> 收缩后的那个代表点叫「花托（base）」。

算法主干（本课全手写，见脚本）：

1. 从每个**未匹配点**出发做 BFS 找增广路（树上交替标「外点 / 内点」）；
2. 搜索中遇到一条「同层相连」的边 → 找到奇环，求出环上两点的**最近公共祖先**（花托），
   把环上所有点的 `base` 统一成花托 → **这就完成了「缩花」**；
3. 收缩后继续 BFS；一旦到达**另一个未匹配点** → 找到增广路；
4. 沿 BFS 树**翻转匹配**（增广），配对数 +1；
5. 对每个未匹配点重复，直到无法增广——**Berge 定理**保证此时即为最大匹配。

复杂度 $O(V^3)$（本课实现为经典版本；用并查集优化到 $O(V^3)$ 常数更小、
带权重版 $O(V^3)$ 即最大权匹配 / KM 的推广）。

## 五、关键代码片段

```python
def lca(a, b, match, p, base):
    """求 BFS 树上 a、b 在『花根』意义下的最近公共祖先 = 花托。"""
    used = set()
    while True:
        a = base[a]; used.add(a)
        if match[a] == -1: break
        a = p[match[a]]
    while True:
        b = base[b]
        if b in used: return b
        b = p[match[b]]

def mark_path(v, b, child, match, p, base, blossom):
    """把 v 到花托 b 的路径上所有点标成『花内』，并把 base 改成花托（缩花）。"""
    while base[v] != b:
        blossom[base[v]] = True
        blossom[base[match[v]]] = True
        p[v] = child
        child = match[v]
        v = p[match[v]]
```

遇到同层边 → `lca` 求花托 → `mark_path` 把整朵花缩成 `base` 为花托的超点，
再把花内点重新入队继续搜索。**「缩花—搜索—展开」就是带花树的全部灵魂。**

## 六、结果解读（10 问之 8：交付物是什么）

**真实决策背景**：12 名护士、20 条可搭班关系边（刻意织入三个奇环）。

- **带花树**：最大匹配 = **6 对**，**全部 12 人配齐**，一次不落。
  配出的搭档：A-B、C-L、D-G、E-F、H-J、I-K。
- **暴力枚举裁判**（位掩码记忆化递归）：最大匹配 = **6 对** —— 与带花树**完全一致**。
- **对照一 · 贪心极大匹配**：只配出 **5 对**（看到边就配，掉进局部最优，少 1 对）。
- **对照二 · 硬套二分图匈牙利**：只配出 **5 对**（把非二分图强拆左右，丢了最优）。
- **随机压力测试**：20 张随机一般图，带花树与暴力真最优**全部一致**——算法正确性多尺度验证。

**交付物不是「配对方案」本身，而是：**

> **① 一个「人人都配得上、配对数最大」的方案；② 一份「换任何别的算法都会少配一对」
> 的反例证据；③ 一个经随机图核验过的、可在多项式时间内处理大规模配对的算法工具。**

**业务上的解释**：护理部若用贪心拍脑袋配对，看似每步都配上了「好搭档」，
结果最后**总有 2 名护士落单**；带花树能保证**只要图上存在完美匹配，就一定把人配齐**——
这正是「精确算法」相较「启发式/贪心」在**关键人力调度**上的价值。

## 八、经验与避坑（写入 README 避坑记录）

1. **〔本课实现第一大坑〕增广函数不能沿用「缩花前的父指针」乱翻**：
   初版 `augment` 用 `while v!=-1: ... v = match[pv]` 却**没有把 `match[pv]=v`**，
   导致匹配**不对称**、一个点出现在多对里——输出 8 条「配对」而实际只有 4 对。
   正解：翻转时**必须双向赋值** `match[v]=pv; match[pv]=v`，并沿
   「父节点原来的匹配伙伴」继续向上。
2. **`find_path` 的返回值语义要统一**：初版返回二元组 `(to,v)` 后又按「两个端点都翻」
   处理，与「沿父指针单链翻转」的 augment 冲突；改为**只返回另一个未匹配端点 `v`**，
   由 `augment(v)` 沿 `p[]` 单链翻转，逻辑才自洽。
3. **遇到同层边要判「已长在搜索树上」而不是「已访问」**：
   判据用 `to==root or (match[to]!=-1 and p[match[to]]!=-1)`，
   即 to 有匹配、且它的匹配伙伴已经在树上——这才是真正的「同层相连（奇环）」。
   若只判 `used[to]`，会把花内点误判、漏缩花。
4. **独立裁判必须真的独立**：用**位掩码记忆化暴力枚举**（小规模精确解）交叉验证
   带花树，并**追加 20 张随机图压力测试**——算法类课程最可靠的正确性凭据
   （与 Day21 Held-Karp、Day22 匈牙利同一做法）。
5. **教学实例要刻意织入奇环**：本例数据特意设计了 **3 个奇环**（三角形 A-B-C、
   三角形 H-I-J、以及跨科室的长边），并且**让贪心/硬套二分都恰好少 1 对**，
   这样「一般图 ≠ 二分图」「贪心 ≠ 最优」两个教学点才立起来
   （**教学数据要刻意设计以暴露算法行为**，与 Day22/24/25/26/31/33/34/35/36/37/38 同一教训）。
6. **图输出路径用 `__file__` 锚定**（参照 Day36/37/38 教训），任意 cwd 运行都落对位置。
