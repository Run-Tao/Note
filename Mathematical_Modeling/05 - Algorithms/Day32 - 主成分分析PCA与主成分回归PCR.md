## 一、这一课解决什么决策

Day9–Day13 的信贷家族有一个**共同的隐含前提**：**"指标之间互不打架"**。

可现实数据里，指标常常**高度重叠**：

- 企业"营收、总资产、员工数、订单量"几乎是同一件事的四个说法（都随规模涨）；
- "利润率、经营现金流"也高度同步；
- 把它们一股脑塞进线性回归，会发生**多重共线性（Multicollinearity）**。

于是风控经理会遇到两个非常具体的麻烦：

> "**为什么我把某个指标加进来，另一个指标的系数符号就反了？**
> **为什么同一份数据换个样本，这几个系数能差好几倍？**
> **到底哪个指标才是真正在决定风险？**"

这不是玄学，是**共线性**在数学上的必然结果：当解释变量近似线性相关时，
OLS 解 `β = (XᵀX)⁻¹Xᵀy` 里的 `XᵀX` **近乎奇异**，逆矩阵对噪声极度敏感
——系数**方差爆炸**、**符号乱变**、**无法解释**。

今天要教的 **主成分分析（Principal Component Analysis, PCA）** 及其回归版
**主成分回归（Principal Component Regression, PCR）**，正是回答这个问题的主流框架：

> **把相关的一堆指标，旋转成少数几个"互不相关"的新维度（主成分），
> 再用新维度做回归。** —— 既压维、又治共线、还能给出"业务维度"的解释。

## 二、PCA 在数学上做了什么

设标准化后的数据矩阵 `Z`（n 个样本 × p 个指标）。PCA 本质是一次**正交旋转**：

$$
Z = U S V^{\top},\qquad
\underbrace{T = ZV}_{\text{主成分得分}},\qquad
\text{第 }k\text{ 个主成分解释方差比} = \frac{s_k^2}{\sum_j s_j^2}
$$

- `V` 的列 = **载荷**（loading）：第 k 个主成分是原始指标的哪种线性组合；
- `T` 的列 = **得分**（score）：每个样本在新维度上的坐标；
- 关键性质：**主成分两两正交**（`TᵀT` 是对角阵）——**回归时彻底没有共线性**。

**为什么要标准化**：PCA 找的是"方差最大"的方向，若不做标准化，
量纲大的列（如营收 vs 利润率）会霸占第一主成分，结论完全错。

**怎么读结论**：载荷告诉你每个主成分"是什么"。本例 PC1 在营收/资产/员工数上载荷大
→ 它是**"企业规模"**；PC3 在负债率上正、在成立年限上负 → 它是**"风险敞口"**。
**主成分不是新造的抽象变量，而是给一堆撞车指标起的"业务小名"。**

## 三、PCR：用主成分做回归

取前 `q` 个主成分做 OLS，再映射回原变量空间：

$$
\beta_{\text{PCR}} = V_{[:,:q]}\,\beta_{T}
$$

**要点**：`β_PCR` 是**有偏**的（主动丢掉了后 p−q 个方向），但**方差大幅降低**。
共线性越强，这个"用偏差换方差"的交易越划算——这就是**偏差-方差权衡**。
（Ridge 回归是另一种治共线性的思路：不丢方向、而是把系数往 0 拉。）

`q` 怎么定？工程惯例：取**累计解释方差 ≥ 90%** 的最小 q。

## 四、实测结论（一家农商行的小微企业违约损失预测）

数据：600 家企业的 8 个指标由 **3 个潜在因子**（规模 / 盈利 / 风险）生成。
`.venv` 实际跑通结果：

**① 共线性确实严重**：VIF = 13.5 ~ 24.5（**普遍 > 10**）、条件数 12.3。

**② 预测精度对照**（测试集 RMSE）：

| 方法 | 测试 RMSE |
|---|---|
| OLS（全 8 指标） | 0.563 |
| **PCR（q=3）** | **0.553** |
| Ridge | **0.547** |

→ 共线数据上，**降维后的 PCR 反而比 OLS 更准**（少即是多）。

**③ ⭐ q=3 恰好等于真实的 3 个潜在因子**：用"累计方差 ≥90%"选出的维度数
**正好复原了数据背后的业务结构**——这是 PCA 最漂亮的地方：**它从相关关系里
"猜"出了你没告诉它的真实维度。**

**④ ⭐ 系数稳定性提升约 10 倍**（Bootstrap 300 次重采样）：

| | OLS 系数标准差 | PCR 系数标准差 |
|---|---|---|
| 平均 | ~0.105 | **~0.012** |

→ PCR 的系数几乎不再"乱抖"，**风控报告里的结论可复现、可信**。

## 五、交付给决策者的是什么

不是"一个模型"，而是一套**能解释 + 能落地**的东西：

1. **几个业务维度**（PC1=规模、PC3=风险）：一句话说清"风险由什么决定"；
2. **一个稳定的预测**（PCR）：用于计提拨备；
3. **一个维度个数的选择**（q 扫描 / 90% 方差线）：告诉决策者"压到几维最划算"；
4. **一份稳定性证据**（Bootstrap）：证明结论不是噪声的巧合。

## 六、这一课的边界（重要）

- PCA/PCR **是"旋转 + 截断"，不是因果模型**；丢掉的主成分方向**可能恰含信号**——
  本课 q=3 表现好，是因为真实信号就在前 3 维；**若信号藏在尾部小方差方向，PCR 会翻车**。
- 主成分**不唯一**（差一个正交旋转/符号）——只谈"方差解释"与"载荷模式"，不谈"唯一系数"。
- 需**标准化**；且 PCA 是**线性**方法，非线性流形要用 kernel PCA / t-SNE / UMAP。

## 七、10 问速答

1. **解决什么决策**：多指标撞车时的稳定预测 + 维度解释。
2. **输入**：n×p 的相关指标矩阵 + 目标 y。
3. **输出**：主成分方向/得分、q 的选择、PCR 预测、系数稳定性。
4. **核心机制**：正交旋转 + 截断（偏差换方差）。
5. **为什么不是直接 OLS**：共线下 OLS 系数方差爆炸、符号乱。
6. **代价是什么**：系数有偏、丢失尾部方向、可解释性需靠载荷转译。
7. **怎么定 q**：累计解释方差 ≥90%（或交叉验证）。
8. **怎样验证**：Bootstrap 稳定性 + 测试集误差 + 载荷是否与业务对得上。
9. **和 Ridge 什么关系**：都在治共线；PCA 丢方向、Ridge 缩系数，常一起用。
10. **一句话**：**指标撞车时，先把它旋转成互不相关的少数"业务维度"，再谈回归。**
