# Day25 · 二部图最大匹配（Maximum Bipartite Matching）与 König 定理

> 代码：[[2026-09-25/README|08 - Python/daily/2026-09-25]]；脚本 `max_matching_konig_theorem.py`；图 `max_matching_konig_theorem.png`。
> 前置：[[Day22 - 指派问题匈牙利算法与二分图匹配]]、[[Day14 - 图论三件套最短路最小生成树最大流]]、[[Day24 - 稳定婚配Gale-Shapley与延迟接受]]。

## 一、这道题在问什么

某团队有 **5 个岗位** A1–A5，手头有 **4 位候选人** B1–B4。不是每个候选人都能干每个岗位，"能胜任"关系如下：

| 岗位 | 能胜任的候选人 |
|---|---|
| A1 | B1, B2 |
| A2 | B1 |
| A3 | B1 |
| A4 | B2, B3 |
| A5 | B3, B4 |

问：**最多能同时安排多少个岗位有人干？**（每人只能占一个岗，每岗最多一个人。）

一眼看去 4 个候选人应该能填 4 个岗，但要注意 **A2、A3 都只会 B1 的活**——两个人抢一个候选人，注定有一个岗位空着。这个"到底最多配几对、是哪几对、卡在哪里"的问题，就是**二部图最大匹配**。

## 二、10 问逐条回答

### 1. 解决什么问题？
在一个**二分图**（左部、右部，边只跨两侧）里，求**最多能选多少条互不共用端点的边**。现实翻译：最多能安排多少个岗位/多少人配对成功、最多能匹配多少份工单给资源、课程 ↔ 教室、学生 ↔ 导师、司机 ↔ 车辆、捐受器官配对。

### 2. 什么情况下使用？
- 两组对象要**建立一对一关联**；
- 关联有**可行性限制**（不是两两都能连），但**没有成本/权重**（或者权重要另算）；
- 问的是"**最多能连多少**"，而不是"怎么连总成本最低"。

### 3. 为什么适合？（模型的数学结构）
把"岗位-候选人"建成二分图 $G=(L\cup R, E)$，问最大匹配 $M$。它和 Day22 指派问题的关系非常关键：

| | Day22 指派 | **Day25 最大匹配** |
|---|---|---|
| 图 | 二分图 | 二分图（同一结构） |
| 边 | 有权重（成本/工时） | **无权**（只有"能不能"） |
| 要求 | 通常**完美匹配**（人人有活） | **不要求覆盖全部**，只要数量最大 |
| 目标 | 总成本最小 | **匹配数最大** |
| 算法 | 匈牙利（带权） | **增广路 / 最大流**（无权） |
| 是否有完美匹配 | 强行构造 | **未必存在**（本例只有 4 对） |

**先问有没有完美匹配，再问最优——这正是 Day25 相对 Day22 的增量**：Day22 默认"人岗数量相等且总能配对"，Day25 先解决"**根本配不配得满**"。

### 4. 变量 / 参数 / 目标 / 约束
- **决策变量**：$x_{ij}\in\{0,1\}$，岗位 $i$ 是否安排候选人 $j$；
- **目标**：$\max \sum_{(i,j)\in E} x_{ij}$（匹配边数最大）；
- **约束**：$\sum_j x_{ij}\le 1$（每个岗位至多一人）、$\sum_i x_{ij}\le 1$（每人至多一岗）、$x_{ij}$ 仅在可胜任的边上取值。

这是个 **0-1 整数规划**——但因为是二分图匹配，约束矩阵**全幺模**（同 Day23 运输问题），**LP 松弛天然给整数解**，所以有多项式精确算法（增广路 / 最大流），**绝不是 NP-hard**。

### 5. 怎么求解？
**核心思想：增广路（Augmenting Path）。**

给定一个匹配 $M$，一条**增广路**是"从**未匹配点**出发、**未匹配边→匹配边→未匹配边→…** 交替、终点也是**未匹配点**"的路径。**Berge 定理**：$M$ 是最大匹配 $\iff$ 不存在增广路。

于是算法就两步：
1. 从每个尚未匹配的左点出发，用 DFS/BFS 找一条增广路；
2. 找到就把路上所有边**匹配状态翻转**（未匹配的变匹配、匹配的变未匹配），匹配数 +1；找不到说明该点再也配不上。

这就是 **Kuhn 算法（匈牙利算法的无权版）**。也可以把二分图建成网络 `源→左部→右部→汇`（边容量全为 1），**最大流值 = 最大匹配数**（本例两种解法都给出 4）。

### 6. 为什么贪心会错？
"按顺序谁先来谁先占"的贪心会把自己堵死。例如让 A1 先抢走 B1，则 A2、A3 全哑火；而正确做法是 **A1 让出 B1 去配 B2**，把 B1 留给非它不可的 A2/A3。**增广路正是实现这种"交换/让位"的机制**——它允许已匹配的边反向让路，故能纠正贪心的局部错误。

### 7. 现实变体怎么改模型？
- **带权重** → 变成指派问题（Day22 的匈牙利带权版 / 最小费用流）；
- **左部或右部数量差很多** → 增广路天然处理（不够就配不满，如实反映）；
- **想要"最少的人/资源覆盖所有任务"** → 切换为**最小点覆盖**（见下 §9）；
- **想要的不是配对而是"互不冲突的最大集合"** → 切换为**最大独立集**（见下 §9）。

### 8. 怎么验证结果对？
- **三法交叉**：手写 Kuhn 增广路 = 手写最大流（Dinic）= 暴力穷举，本例都给出 **4**；
- **增广路存在性**：算法结束后遍历所有非匹配点，确认再也找不到增广路；
- **小规模穷举真值**：枚举所有匹配组合取最大（本例穷举 = 4）；
- **定理核对**：随机生成 300 组二部图，逐组验证 König 定理的等号成立且构造出的覆盖合法（本例 300/300 全过）。

### 9. 附赠定理链：König 定理与最大独立集

这是本篇最精彩、也最常在论文/面试里被追问的部分——**二分图里三个看似无关的量，其实是同一个数**：

$$\boxed{|最大匹配| = |最小点覆盖| = |V| - |最大独立集|}$$

- **点覆盖**：一族点，使图中**每条边至少有一个端点在族里**（"用最少的人盯住所有关系"）；
- **独立集**：一族点，**内部两两不相邻**（"选出最多互不冲突的人"）。

**König 定理**（二分图专有，一般图**不成立**）说 **最小点覆盖大小 = 最大匹配大小**。它的**构造性证明**正是我们的验证方法：

> 从**所有未匹配的左点**出发，沿**未匹配边正向走、匹配边反向走**做交错搜索（"交替可达"）。
> 则 **最小点覆盖 = （左部中【不可达】的点）∪（右部中【可达】的点）**。

本例实测：不可达左点 = {A1, A4, A5}、可达右点 = {B1} → **最小点覆盖 = {A1, A4, A5, B1}，大小 4 = 最大匹配**。由 $|最大独立集| = |V| - |最小点覆盖| = 9 - 4 = 5$，独立集 = {A2, A3, B2, B3, B4}——验证内部确实没有任何一条边相连。

### 10. 交付物是什么？
**最大匹配方案 + 匹配数 + 瓶颈诊断**（哪些岗位配不上、卡在谁身上），以及（若论文需要）**由定理链得到的等价指标**：最小点覆盖（"最少用几个人/资源就能覆盖所有关系"）、最大独立集（"最多能同时保留多少互不冲突的对象"）。

## 三、关键结果（仓库 `.venv` 实跑）

**最大匹配 = 4**（三法一致：Kuhn 增广路 = Dinic 最大流 = 暴力穷举）：

| 匹配边 | 岗位 | 候选人 |
|---|---|---|
| A1 – B2 | A1 | B2 |
| A2 – B1 | A2 | B1 |
| A4 – B3 | A4 | B3 |
| A5 – B4 | A5 | B4 |

- **瓶颈诊断**：未匹配岗位 = **A3**；无人胜任的候选人 = 无。**因为 A2、A3 都只能干 B1 的活，两个岗抢一个候选人，注定空一个岗**——这就是 Hall 定理说的"左部子集 {A2, A3} 的邻居只有 {B1}，邻居数 1 < 2"。
- **König 定理实测**：最小点覆盖 = {A1, A4, A5, B1}，**大小 4 = 最大匹配**，且经检验覆盖了所有边（穷举出的最小覆盖大小也是 4，一致）。
- **最大独立集**：{A2, A3, B2, B3, B4}，**大小 5 = |V|(9) − |最小点覆盖|(4)**，内部无相邻边。
- **敏感性**：逐个移除一个岗位看最大匹配数变化——移除 A1/A4/A5 → 降到 **3**；移除 A2/A3（本来就多余的那个）→ 仍为 **4**。**这直接指出谁是"关键岗位"：A1、A4、A5 一人缺阵就少配一对。**

## 四、要点提炼

- **最大匹配补的是"无权 / 求最多"的配对场景**：Day22 指派先假定"人人有活、求总成本最小"，Day25 先回答**"到底配不配得满、最多几个"**——两者共用二分图结构，目标却完全不同；
- **增广路 = 会"让位"的匹配**：它允许已配好的边反向退让，从而纠正贪心的局部死锁，也是最大流建模的底层机制（最大流值 = 最大匹配数）；
- **König 定理是二分图的"免费午餐"**：$|最大匹配| = |最小点覆盖|$，把"求最多配对"和"用最少点覆盖所有关系"变成**同一个数**，且构造方法是可执行的（交错可达 → 取不可达左点 + 可达右点）；再搭上 $|最大独立集| = |V| - |最小点覆盖|$，三量一链；
- **注意适用范围**：König 定理**只在二分图成立**，一般图（如三角环）最大匹配 ≠ 最小点覆盖；
- 至今 Day14 / Day22 / Day23 / Day24 / Day25 合起来，**图论-匹配家族**已成体系：最短路/MST/最大流 → 指派（带权完美匹配，求最省）→ 运输（最小费用流）→ 稳定婚配（求最稳）→ **最大匹配（无权，求最多）+ König 定理**。

## 五、常见问题

> [!question] 有完美匹配的判断标准是什么？
> 用 **Hall 定理**：对左部**任意**子集 $S$，其邻居集合大小 $\ge |S|$，则存在覆盖左部全部的匹配。本例 $S=\{A2,A3\}$ 的邻居只有 $\{B1\}$，$1<2$，故**不存在**完美匹配——这正是"最多配 4 对"的根因。

> [!question] 最大匹配和最小点覆盖为什么要一起讲？
> 因为它们**数值相等**（König），而且求法互通——知道了最大匹配，就能通过交错可达**构造**出最小点覆盖。很多"最少派几个人覆盖所有关系"的实际问题，直接调最大匹配算法就能解，不必另写点覆盖求解器。

> [!question] 这和"最小费用流"什么关系？
> 最大匹配是**最小费用流在"全部边费用为 0、容量为 1"下的特例**（只最大化流量，不关心费用）。反过来，给边加费用就回到 Day23 的最小费用流/指派。**三个模型是一根轴上的不同投影**。
