# Day 11 — 信贷风控(三)：既给概率、又给"人话规则"（决策树 / 随机森林）

> 锚点：[[Learning_Roadmap|Learning Roadmap]] Level 8 · 数据分析与机器学习 / 监督分类。
> 这是"分类三连"的收官。**Day9 KNN** 是记忆型（不训练、查邻居投票、给不出规则）；**Day10 Logistic** 是参数化、给概率但边界是直线；这一课补上第三种口味——**树模型**：它天然刻画**非线性与特征交互**（"负债率高**且**收入低才危险"），而且长出来的是一棵能直接念给业务听的 **if-else 规则树**；再用**随机森林**把许多棵高方差的小树集成成稳健模型。

## 0. 一句话总结

决策树干的是**一场贪心的二十问游戏**：每次挑"最能一刀把好坏分开"的特征和阈值（用**基尼不纯度**衡量纯度），合法地把客户往两边赶，直到结点够纯或到深度上限——叶子的"坏客户占比"就是**违约概率**。树本身**极可解释**（能写出规则），但**极不稳、易过拟合**（数据抖一点，整棵树形状就变）。**随机森林**的解法是"三个臭皮匠"：**自助采样**拿不同数据子集 + **每次只随机抽几个特征**来建许多棵**彼此不太一样**的树，预测时**投票/平均**——个体方差被平均掉，泛化更稳。

## 一、这个方法解决什么问题？（10问之1）

**决策对象：既要"能不能贷"的判断，又要"为什么拒"的依据。**

银行的信贷员不接受一个只会说"这人 62% 违约"的黑箱——监管和客户都要求**拒贷理由**（"因为您负债率超过 55% 且月收入低于 8000"）。Logistic 给出系数方向，但边界是全局直线，抓不住"高负债 **且** 低收入才危险"这种**交互**；KNN 连规则都给不出。决策树正好补位：它**自动发现交互**（切完负债率再切收入），且产出是**可读的规则**。这就是本课的真实决策场景——**在 600 名历史客户上训练一个"说得清理由"的信贷评分模型**。

## 二、问题的实质：把"最会分类的问题"拆成"最会分类的二叉树"

- **基尼不纯度** $G=1-\sum_k p_k^2$：一个结点里类别越"杂"越大（二分类最乱 = 0.5），越"纯"越小（纯结点 = 0）。树的目标就是每切一刀让**子结点加权基尼尽量小**。
- **贪心最佳切分**：遍历每个特征的每个候选阈值，选 **加权基尼下降 = 父结点不纯度 − (左占比×左不纯度 + 右占比×右不纯度)** 最大的那一刀。注意是**贪心**——只看当前这一刀，不考虑对后面的影响（全局最优要 NP 难，贪心是工程妥协）。
- **递归长树**：切完对左右两边**重复**这个动作，直到纯 / 到深度上限 / 样本太少 → 长成一棵二叉树。
- **叶子即概率**：叶子里的"违约样本占比"就是该叶子的违约概率。
- **为什么是 if-else**：一条从根到叶的路径 = 一串阈值判断合取，天然是"若 负债率>55% 且 收入<1.2 → 违约概率 71%"。

## 三、核心矛盾：单棵树"太聪明反而学坏"（偏差-方差）

- 树**不限制深度**能长到每个叶子只装一个样本 → **训练集准确率 100%、测试集崩**。这是**高方差**：数据换一批，树形状大变。
- 控制手段：**max_depth（最大深度）**、**min_samples_leaf（叶子最少样本数）**，本质是"**故意不让它把训练集背下来**"。
- 本课实测（测试集 180 人）：深度 1→0.739、深度 2→0.767、深度 4→**0.761（甜点区）**、深度 10/不限 →训练集飙到 0.843 但测试跌回 0.733。**训练测试的喇叭口就是过拟合的形状**。

## 四、随机森林：用"多样性"换"稳健"

单棵树高方差，那就造一堆**不一样**的树再平均。两处"随机"制造差异：

1. **自助采样（Bagging）**：每棵树从原数据**有放回**抽同样多（约 63% 被抽中，其余"袋外"），让树看到不同的数据。
2. **特征随机**：每次切分只从**随机一小撮特征**里挑最优（而非全部），逼树们从不同角度观察。

最后**分类靠投票**（本课取平均概率）。原理：**一堆不相关的、偏高方差但无偏的树，平均后方差被摊薄**（方差 $\propto 1/n$，且相关性越低降得越多）。所以森林通常**比单棵树稳**。本课实测森林 0.733 vs 单树 0.761——**没赢**！这恰恰是重要一课：**小数据 + 深树下限 + 特征只有 2 个时，随机森林的优势发挥不出来**（特征空间太小，"随机抽特征"制造不出多样性，反而每棵树都更弱）。集成不是万能药，**数据量和特征维度是它的前提**。

## 五、与 Day9/Day10 的三相对照（本课最有价值的收获）

| | Day9 KNN | Day10 Logistic | Day11 决策树 |
|---|---|---|---|
| 类型 | 记忆型/惰性 | 参数化（线性） | 参数化（非线/树） |
| 决策边界 | 不规则、随样本乱长 | 全局**直线** | **轴对齐台阶**（自动分段） |
| 给概率 | ✗ 硬标签 | ✓ sigmoid | ✓ 叶子占比 |
| 给规则/解释 | ✗ | 系数方向 | ✓✓ **可读 if-else** |
| 抓特征交互 | 隐式 | ✗ 需手工造交互项 | ✓✓ **自动发现** |
| 弱点 | 预测慢、需标准化 | 只能线性 | 不稳、易过拟合 |

**选型直觉**：要"概率 + 方向可解释"→ Logistic；要"人能念的硬规则"→ 决策树；非线性复杂但数据量够 → 随机森林/GBDT；样本小、无规则诉求 → KNN。

## 六、结果怎么读（拒绝纸上谈兵）

- **混淆矩阵**（深度 4 树）：好客户判对 99、**拒错好客户 19**（误伤营收）、**漏放坏账 24**（损失本金）、坏客户判对 38。两类错误此消彼长——和 Day10 一样，**判定线是业务决策**不是算法产物。
- **特征重要性**：负债率 0.675 ≫ 收入 0.325。**负债率是主力判别变量**，符合"银行先看负债率"的常识；这也是一次**特征筛选**信号（可考虑先约简冗余特征）。
- **方向校验**：高负债率测试客户的平均违约概率显著高于低负债率组（已断言）。

## 八、一句话带走

**决策树 = 贪心二十问游戏**（每次挑最纯的一刀，长成可读规则）；它天生会抓交互、给概率，但**高方差**；**随机森林靠"样本自助 + 特征随机"造多样性来平均方差**，代价是失去单棵树的可读性、且需要足够的数据/特征维度才发挥优势。**别迷信集成——小数据上它可能跑输单棵树。**
