## 一句话

11 个需求片区、5 个候选站点，同样是"选几个站"，**集合覆盖、最大覆盖、p-中值给出三个不同的解**；
而真正决定"开几个"的不是模型，是**响应口径**——城区 11 / 乡镇 18 分钟 → 3 个站；
乡镇放宽到 20 分钟 → **1 个站**。

## 三个教学点（都已写成断言）

1. **最优解不唯一时，求解器会替你挑**——3 个覆盖最优集里最差的那个平均慢 11.8%
   （每车年多跑 13.67 千人·分，即**每次呼救多等 55.6 秒**）。解法：先覆盖定 $p$，再中值定站（字典序两阶段）。
2. **别在口径选错的模型上求最优**：单一口径 40 分钟时整表最长才 26 分钟，题目退化成"开 1 个站"。
3. **平均值 + 最远点必须同时报**：均值 7.83 分钟掩盖了河湾 14.03 分钟的孤立暴露，
   而这一点**加站也解决不了**（$p=4$ 时最远仍是 14.03）。

## 踩坑（全部实跑暴露，详细见教案 §6）

1. 口径设成"全县 40 分钟"→ 全表最长 26 分钟 → 模型答"1 个站"，全课结论反转（返工 3 轮）。
2. `main()` 里重算 `TIME_LIMIT`，把模块级常量静默覆盖回 15/40，前面修正全部失效。
3. `TIME` 是 M×N，`cover` 必须 N×M；把 TIME 直接当 cover 传进去，**约束行只有 4 条，解出 1 个站且 status=Optimal**。
4. 覆盖判定 `sum(axis=1) == 0` 漏写 `not`，把"一个点都盖不住"判成可行 → 又解出 1 个站。
5. 手填距离表与平面坐标不一致 → 改成**距离由坐标计算**，表与图标本自洽。
6. `evaluate()` 的 mask 方向（候选站 vs 需求点）混淆，报 `IndexError`。
7. 小规模覆盖问题用**精确枚举**当裁判（31 种组合），不迷信求解器（Day59 HiGHS presolve 假最优的教训）。
8. 断言用于**实例体检**：`均值差 > 0.3` 一挂，说明实例没立住，要调数据而不是放松断言。
