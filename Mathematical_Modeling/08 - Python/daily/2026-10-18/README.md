# Day47 · 置换流水车间调度 FSP：NEH 构造 + 迭代贪心 IG（代码）

> 教案正文见 [[Day47 - 置换流水车间调度FSP_NEH构造与迭代贪心IG]]（`05 - Algorithms/`）。
> 脚本：`flowshop_neh_ig.py`；图：`flowshop_neh_ig.png`。
> 运行：`cd /home/ubuntu/Note && ./.venv/bin/python "Mathematical_Modeling/08 - Python/daily/2026-10-18/flowshop_neh_ig.py"`（约 25 秒）

## 一句话

**县域果酱厂 5 道工序、14 批原料，定加工顺序使整条线最早收工（makespan）**——
「瓶颈优先」这条车间铁律给出 134h，比 LPT（130h）还差；**NEH 构造 5 毫秒给出 124h**，
**迭代贪心 IG 从 LPT 粗解（130h）出发收敛到同样的 124h**；小规模 7 批暴力枚举证明
两者都命中了**真最优（68h）**，大问题 124h **距最强下界 122h 仅 1.6%**。

## 真实决策背景

果酱厂 5 台设备串联：**清洗去核 → 蒸煮浓缩 → 灌装封口 → 贴标打码 → 装箱入库**。
14 批不同水果，每批按同一顺序走完 5 道工序；设备不能并行处理两批。

- **决策**：14 批的加工顺序（一个排列）；
- **目标**：makespan（最后一批装箱入库的时刻）最小；
- **现实口径**：完工每提前 1 小时 = 5 台设备 + 14 个工位少开 1 小时；
- **病根**：蒸煮浓缩总工时 117h（占比近四成），是产能瓶颈。

**为什么「瓶颈优先」不灵？** 因为瓶颈设备本来就不会空（总工时最大），把长活先喂给它只会让下游灌装机瞬间吃满、然后长时间断粮——**损失不在瓶颈机，而在下游等件**。

## 避坑记录

1. **测试数据要先「体检」（本日主坑）**——原计划直接沿用 2026-10-17 目录里那份半成品脚本（`flowshop_neh_ig.py`，未验证，实跑时断言即挂）。体检（脚本 `Resources/diagnostics/2026-10-18_diag_flowshop_legacy.py`，可复跑）发现：
   - 数据本身自洽（285 = 285），但 **「瓶颈优先」141h / LPT 140h / SPT 142h 四种直觉规则挤在 140~143h**；
   - **NEH 138h，IG 从 NEH 出发 300 次迭代一步无改进（138→138→138）**——教学点「IG 能把 NEH 撬开」彻底落空；
   - 更糟的是 **它的脚本里下界写成了 126h，却把 138h 的解报告为「超下界 6.2%」，而同一脚本里 LB 与解的关系从未被断言校验过**。
   **教训：跑算法之前先跑一致性检查**——① 数据行和/列和要对上；② **四种不同机制的方法给出几乎相同的数 = 该数据没有区分度**，不是算法好；③ **下界比解短太多** 或 **IG 一步不动**，都说明实例设计有问题。本日重新设计工时表（瓶颈 117h / 下游 27~64h，总负载 309h，符合真实果酱线），教学链（LPT 130h / NEH 124h / LB 122h）才立起来。
2. **下界必须「逐工序交代开工链 + 负载 + 收尾链」**——最初用 `max(工序总工时) = 117h` 当下界，它**比 NEH 的 124h 还短**，进而被错误地当成"解离最优还有 6%"的证据。真正的合法下界是 **M1：`开工链 + T_k + 收尾链` = 122h**，加两把校验：`LB ≤ 解`、`LB ≤ 小规模真最优`。
3. **「相邻双机精确界」的子集 DP 很快但很松**——只保留相邻两台机器时，聚合后的每件更短、也看不见首件开工链，所以 M2(119h) 反而不如 M1(122h)；**多个下界必须取 max 而不是相加**，而且要把「哪个更强」讲清楚。
4. **Johnson 规则在「双机松弛」上不是自动精确**——聚合出相等的 a、b 时，Johnson 的排序不再是精确 DP；本课用 **Held-Karp 式子集 DP + 非支配剪枝**（n=14 秒级）给出精确值。
5. **「最优解里首道工序一定无空闲」这个断言是错的**——本课第一版断言 `idles_neh[0] < 1e-9` 直接挂掉。FSP 里首台设备**每次都要等上一批的上一道工序**，它当然会空。正确的验证是 **`瓶颈机空闲 == makespan - 瓶颈总工时`**（这台设备确实是"除了首件等待以外全程无空"）。
6. **IG 的「改进」要诚实归因**——本课 10 个种子全部收敛到 124h，说明这个实例的搜索地形很平坦；**不能写成「IG 比 NEH 更强」**，而应写成「IG 从粗解出发即可收敛到 NEH 级解」，并把「NEH 5ms vs IG 2s」的代价差如实列出。
7. **「超下界 xx%」的说法要按正负号处理**——`100*(ms/lb-1)` 为负时是「比下界短」，说明**下界本身算错了**，不能当"好"来报。本课直接改成 `距下界 +x%` 并把 M0 的失败案例写进教案。
8. **图内特殊字符**——`Σ`（U+2211）、`≤`、`→`、`σ` 在 Noto Sans CJK SC 中都有，`⏳`（U+23F3）没有；本项目图上凡是"特殊符号"一律只用 ASCII 或中文字，避免 `-W all` 下出现 glyph 告警。
9. **中文字体注册用 `sans-serif` 回退链**（`font.family="sans-serif"` + `font.sans-serif=[Noto Sans CJK SC, WenQuanYi, DejaVu Sans]`），`-W all` 下 0 条 glyph/findfont 告警。
10. **输出图路径用 `__file__` 锚定**（参照 Day36–46），从任意 cwd 运行都能正确落图。
11. **IG 的接受温度取 `0.5 × 平均单位工时`**，与 Day46 的"温度量级 = 单步扰动"同一思路；温度过大会退化随机搜索、过小则退化成"只接受改进"（回到爬山）。
