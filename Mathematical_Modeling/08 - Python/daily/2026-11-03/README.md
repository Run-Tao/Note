## 一句话结论

**块数不是你选的：2 块吊不动（56.3 t）、3 块装不下（37.6 t），4 块是设备卡出来的下限；
而 4 块最优切点不是均分（10/20/30）而是 11.25 / 21.0 / 30.75——首块顶满 32 t、末块压到 26 t 不翻身，
把「必须翻身」的块从 4 个降到 1 个，总费从 5.12 万（均分）降到 4.40 万。
「贴着车限切」的贪心与「均分起手 + 局部微调」都只到 4.64 万，差的那 2400 元是离散台阶，不是计算误差。**

## 十问

1. **谁在决策？** 云溪县三桥改造项目的吊装负责人 + 钢构厂分节工艺员（共同决定"哪一刀切在哪个位置"）。
2. **决策是什么？** ① 切几块；② 每刀的纵向位置；③ 每块是否侧放运输（决定要不要翻身多吊一次）。
3. **不做的代价？** 均分 4 块 → 5.12 万（且 4 块全翻身）；均分 5 块 → 5.04 万；贪心 → 4.64 万；DP 最优 → **4.40 万**。
   均分 4 块比最优 **多付 7200 元**，且**多 3 次高空翻身**（风险不计钱，但也进不了账）。
4. **数据从哪来？** 梁长 40 m、总重 112.689 t（均布 2.817 t/m）；拖车 32 t/车、1800 元/车；履带吊 9800 元/天、
   62 t@≤16 m → 46 t@22 m；接头 4600 元/个；吊装 2400 元/次。**全部写在脚本头部常量里，改一行即重算。**
5. **量化目标？** 直接费用（车 + 接头 + 吊次 + 吊车日租 + 现场日开销）+ 翻身块数（风险指标）。
6. **可行域？** 每块 ≤32 t、≤16 m、端点跨距 ≤20 m、块重 ≤ 该处起重量；这些**同时**成立才可行。
7. **对照方案？** ① 等分 2/3/4/5/6 块；② 贪心（贴着 32 t）；③ 均分起手 + 单点局部搜索；④ **连续切分 DP**（块数外层枚举 × 内层区间 DP）。
8. **敏感什么？** 吊车日租、接头费、拖车限重（见脚本敏感性段）。
9. **结论对谁有用？** 吊装单位（切点要"前重后轻"）、钢构厂（首块顶满、末块压低）、监理（翻身次数 = 风险口子）。
10. **哪一步最可能错？** 把"吊不动"当"很贵"；把均分当最优；用局部搜索冒充全局最优；忽略"块端点跨距"只按块中心算起重量。

## 8 条避坑（本讲实跑暴露）

1. `-W error` 下 `json.dump(res, open(...))` 触发 `ResourceWarning` 直接崩 → 必须 `with open(...)`；
2. 浮点 `28.17 > 28` 判定不稳定 → 阈值比较统一加 `1e-9` 容差；
3. DP 里 `round(j*GRID, 6)` 累加误差让 `w > 32` 误判 → 用 `j * GRID` 乘法；
4. "不可行"不要写成 `inf` 价格 → 显式 `feasible=False`，否则比较逻辑会出错；
5. DP 会钻"末刀剁 1 m"的空子（7 块 4 车）→ 加碎块惩罚 + 与手排解对账；
6. 起重量必须按**块端点最大跨距**算，不能按块中心（否则 4 块均分被误判为吊得动）；
7. 局部搜索**不能用于验证最优**（本讲它停在 4.64 万，比 DP 差 0.24 万）→ 用小规模 DP 自己验证；
8. 中文字体注册 Noto Sans CJK SC，`-W error` 下零告警。
