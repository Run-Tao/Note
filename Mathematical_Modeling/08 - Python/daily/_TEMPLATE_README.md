## 语义闸门（入库前逐条打勾，全部来自真实踩坑，共 4 条）

> 来历：Day87–Day89 连续三讲各自暴露一类「数字对、口径错、不报错」的错误。
> 数值断言（断言全过）拦不住它们，必须人工逐条核对。**任一条无法打勾，就不得入库。**

- [ ] **闸门 1 · 统计量对齐**：自己实现的 ARI / 轮廓 / 互信息 / 分位数等统计量，必须与成熟库（`sklearn.metrics` 等）在同一输入上比对一次并打印，差 >1e-9 就停。
- [ ] **闸门 2 · 下标空间**：任何 `ari(a, b)`、`zip`、按索引取值的调用，必须明确「这是簇号、位置下标，还是样本 id」，并在旁边打印一个反例验证（**Day87 假 ARI 1.000 就死在这里**）。
- [ ] **闸门 3 · 无样本筛选 / 去重**：任何在循环里 `continue` / `drop` / `set` 去重的写法，必须累计并打印**丢弃率与被丢对象清单**；丢弃率 >0 就要在 README 说明为什么不影响结论（**Day87 按结果筛样本 / Day88 bootstrap 按身份去重**）。
- [ ] **闸门 4 · 判定逻辑自证**：凡是「due / health / warning / pass-fail」这类判定，必须给出一次**已知反例**（喂一个应当报错的东西，看它有没有报）—— 只验证「好数据能过」等于没验证（**G-003 断言退化为自证**）。
