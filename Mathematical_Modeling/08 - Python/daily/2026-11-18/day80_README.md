## 十问

1. **解决什么问题？** 12 个冷链自提点的单车辆夜班配送，要一条最短闭合路线；问的是「启发式给的答案，凭什么信」。
2. **什么时候用？** 点数上到 20+ 精确算法（Held-Karp 是 $O(n^2 2^n)$）跑不动；只要「够好 + 可复现」的工程解。
3. **为什么适合？** TSP 的邻域结构天然（2-opt 段反转 / or-opt 点移动），增量代价 $O(1)$，一次迭代只算 4 个距离。
4. **数学模型？** $\min L(t)=\sum_{k} d_{t_k t_{k+1}}$，$t$ 为 1..12 的排列，闭合回中心库。
5. **怎么求解？** 构造（扫描法）→ SA（2-opt 70% + or-opt 30%，初温取 $P(\text{accept})=0.85$ 经验公式，几何降温）→ 禁忌（候选 60 个取最优，tenure 7，特赦准则）。
6. **怎么实现？** 判据用**增量**（`delta_2opt`/`delta_oropt`），只有真正接受才 `apply_*`；每步都断言路线合法。
7. **怎么验证？** 三种对照（正常退火 / 永远接受 / 极低初温）+ 8 种子方差 + 1-tree 下界 + 8 次重复看最优解唯一性。
8. **缺点？** 12 点规模太小，两个方法都能到 71.51，**分不出高下**；没有时间窗、多车、容量分割。
9. **替代？** 2-opt 局部搜索 + 多起点、Or-tools/Concorde 精确解、GA、蚁群、LKH。
10. **怎么进论文？** 报构造法差距 → 报「温度/禁忌到底管不管用」的对照 → 报下界给的 gap → 报多次跑的最优解一致性。

## 实跑数字

### 构造法（14 个起点 + 2 个启发式）

| 方法 | L (km) |
|---|---|
| **扫描法** | **74.90** |
| 最近邻（最好起点=黄泥） | 77.95 |
| 最省插入 | 78.56 |
| 最近邻（最差起点=冷水） | **99.71** |

→ **同一个最近邻，只换起点就差 21.76 km（22.4 km 的差距 = 91.4 元/晚）**。构造法的方差比算法本身还重要。

### 三条 SA 链（同样 20,000 步，同一构造起点）

| 链 | L_best (km) | 接受率 |
|---|---|---|
| 正常退火 | **71.51** | 20.6% |
| 永远接受（纯随机游走） | 74.90 | 100% |
| 极低初温（准下降） | **71.51** | 3.1% |

> **这是本讲第一个反直觉**：极低初温（几乎等于纯下降）在这个实例上跑出**一样的结果**。
> 说明 12 点规模上，2-opt+or-opt **邻域本身就足够强**，温度的「逃出局部最优」作用**没有被需要**。
> 「SA 比局部搜索好」在这道题上**不成立** —— 这句必须写进论文，而不是抄教材。

### 8 个种子的 SA（8,000 步）

| 均值 | 标准差 | 最好 | 最差 |
|---|---|---|---|
| 72.29 | 1.01 | 71.51 | 73.59 |

→ 同一算法同一参数，**不同种子差 2.08 km**。所以「我的算法得到 X」必须配一句「跑了几次、方差多少」。

### 禁忌搜索

| 配置 | L_best (km) |
|---|---|
| 有禁忌 tenure=7 | 71.51 |
| **关禁忌（纯下降）** | **71.51** |
| tenure 3/5/7/11/15/23 | 71.51（全同） |

> **第二个反直觉，也是本讲最该写进论文的一句**：
> **禁忌长度从 3 到 23 毫无影响，关掉禁忌也一样。**
> 原因不是禁忌没用，而是 12 点 TSP 的 2-opt 邻域上**没有值得填的坑**——
> 局部最优的质量已经和下界只差 6.14%。
> 「我们用了禁忌搜索」在小题上是**装饰**；要证明它有用，必须换到有**硬约束/时间窗/多车**的问题上，
> 那里局部最优才会真的烂，禁忌才有活干。

### 下界与 gap

| 量 | 值 |
|---|---|
| 最紧 1-tree 下界 LB | 67.37 km |
| SA 最优 | 71.51 km |
| gap | **6.14%** |

> 1-tree 下界是**松弛**（放弃度数约束），所以真最优 ≥ 67.37，**最多还能再好 6.14%**。
> 这是给「启发式解够不够好」唯一诚实的锚 —— **没有下界的「最优」只是「我跑到的」**。

### 稳定性（8 次独立跑，规范化正反向）

**跑出 2 条不同的最优路线**（长度都是 71.51 km，互为反向/等价）：

1. 梅溪 → 石坳 → 双桥 → 冷水 → 新塘 → 南坪 → 太平桥 → 白水 → 枫林坳 → 榕树脚 → 竹山 → 黄泥
2. 南坪 → 太平桥 → 新塘 → 冷水 → 双桥 → 石坳 → 梅溪 → 黄泥 → 竹山 → 榕树脚 → 枫林坳 → 白水

> **这条直接回应 Day79**：Day79 的教训是「基一变，$z$ 可能只掉 6.8%，但方案已经换人」。
> 这里正好是好事的那一面：**两条不同路线，长度完全相同** —— 方案是多解的，报「最优路线」时要给集合，不能给一条。

## 避坑（6 条，全部实跑暴露）

1. 🔴 **`apply_oropt` 与 `delta_oropt` 的下标口径不一致**，是本次返工的主因。第一版 `delta` 吃「点编号」而 `apply` 吃「元组下标」，
   增量与真实变化不符，SA 报出 **−2103.51 km 的负长度**（物理上不可能）。
   **正确做法：所有函数统一用元组下标，并在 `apply` 里 `rest[:k] + (v,) + rest[k:]`。**
2. 🔴 **`rng.integers(0, N-1)` 才是下标上界**：路线长度是 `N-1`，写成 `N-1` 当上界会越界。
   本讲抽了 3 轮才定位：`ValueError: low >= high`。
3. 🔴 **永远接受链会把长度拖到构造解水平**（74.90 = 扫描法本身）—— 这不是 bug，是温度 100% 接受时**纯随机游走**的正常表现，
   正好用作对照。别把它当失败删掉。
4. ⚠️ **1-tree 下界要取「所有根节点的最大值」**，随便挑一个根会得到更松（更小）的下界，gap 被高估。
5. ⚠️ **`-W error` 下 `np.mean` 空列表会告警**：本讲 `initial_temp` 里加了 `if pos else 1.0` 兜底。
6. ⚠️ **中文引号进 f-string 直接 SyntaxError**（Day79 的教训，本讲全程用「」）。
