## 一、这一课解决什么决策

云溪烟叶站刚换了三条电热泵烤房、又引进了两种新式工艺。站长手里的账：

- **6 种烘烤曲线**（传统三段式、低温慢变黄、先蒸后烤、分段升温、带杆密集烤、电热泵烤）；
- 往年记录显示各工艺的达标率差别很大，但**这一季的烟叶含水量偏高，往年数字不作数**；
- 一季只有 **400 炉**（一台一炉、一天一炉），每炉的结果只看得到「达标 / 不达标」。

同时，收购站的 4 户烟农共用**同一间旧烤房**：每户的烟叶按成熟度分两批，第一批先上、第二批后上，
**每一炉只能烘一批**，批与批之间不能中断（中途出炉就毁了）。烟叶在屋里每多放一天掉一档，
损耗按「担数 × 等待天数」计。

要回答四个问题：

1. **先试还是先用最好的？** 前 6 炉各试一遍（「热身」）够不够？
2. **「试」值多少钱？** 一季下来，选错工艺到底亏掉几炉？这要看「冠军领先亚军多少」。
3. **4 户 8 批，谁来先上炉？** 规则排、还是用搜索（UCT）？
4. **UCT 一定比规则好？** 好多少？如果不好，是模拟不够多，还是这个算法根本不该用在这个规模上？

> 两者的共同点：**决策的效果要在做下一条决策之前先看到**，这就是「序贯决策」。
> 两者的区别：前半段是**信息不确定**（P 未知），后半段是**结果确定但组合爆炸**（P 已知，是 1）。

## 二、模型

### 2.1 第一部分：Bernoulli 多臂老虎机

$$a_t\in\{1,\dots,K\},\qquad r_t\sim\mathrm{Bernoulli}(p_{a_t}),\qquad R_T=\sum_{t=1}^{T}p^\star-\mathbb{E}\!\left[\frac{1}{T}\sum r_t\right]\ \ (\text{regret})$$

决策者**不知道 $p$**，只能看到 $r_t$。这就是 [[Day18 - 随机动态优化排队论MMc与MDP值迭代]] 的 $P$ 被换成了「未知 + 要靠试」。

四个策略（全部手写，无第三方 bandit 库）：

| 策略 | 规则 | 一句话 |
|---|---|---|
| 纯贪心 | 每个臂先试一次，然后永远选经验均值最高的 | 「只热身一次」——最常见的错法 |
| ε-贪心 | 以 ε=0.1 概率随机选 | 用固定比例的炉次「交学费」 |
| **UCB** | $\bar\mu_a + c\sqrt{2\ln t/n_a}$，未拉过的臂取 $+\infty$ | 给「没把握」的臂加一个随轮的奖励 |
| **Thompson** | 从后验 $\mathrm{Beta}(s_a+1,\ n_a-s_a+1)$ 抽样，选抽样值最大的 | 用「先验 + 观测」直接算「还敢不敢试」 |

> [!warning] UCB 的 $c$ 不是常数
> 教材写 $c=1$（UCB1），那是给 $T\to\infty$ 的渐近系数。本实例 $T=400$，$\ln T\approx 6$，
> 噪声项 $c\sqrt{2\ln t/n}$ 在这 400 炉里**根本来不及收缩**。实跑：**c=1 亏 45 炉，c=0.25 亏 16 炉**。

### 2.2 第二部分：分批排产（4 户 × 2 批，共用 1 间烤房）

状态 $s=(d_1,\dots,d_4)$，$d_j\in\{0,1,2\}$ = 第 $j$ 户已烘批数；动作 = 选下一户。

$$F(s)=\min_{j:\,d_j<2}\Big[\ \underbrace{t(s)\cdot q_{j,d_j}}_{\text{本批开工时的等待}}\ +\ F(s+\mathbf e_j)\Big],\qquad t(s)=\sum_j d_j\tau_j$$

- $q_{j,k}$ = 第 $j$ 户第 $k$ 批的担数，$\tau_j$ = 每批烘制天数；
- 状态数 $3^4=81$，**直接用 [[Day16 - 动态规划DP设备更新与01背包|DP]] 一步到位**；
- 全部合法序列 $\dfrac{8!}{(2!)^4}=2520$ 种，用**全枚举**核对 DP。

**UCT**（把 UCB 长到树上）：每个节点维护访问次数 $N$ 与累计价值 $W$，
选择 $\arg\max_{\text{child}}\ \overline{W} + c\sqrt{\ln N_{\text{parent}}/N_{\text{child}}}$，展开 → **rollout** → 回传。

> [!important] 本讲最贵的三个实现细节（全部实跑暴露）
> ① **rollout 必须从「刚展开节点的下一步」开始模拟**——写成「从该节点开始」时，根节点会被当成一条模拟，根 N 与子节点 N 差一位；
> ② **不同深度的模拟值不能直接相加**——节点越深，`evaluate(seq, t0)` 里的 t0 越大，值必然越小，于是「越深越被偏爱」，与正确方向相反；
> ③ **「一次建树、逐层下棋」≠「每步重建一棵树」**——后者把学到的东西反复忘掉，实测 100 次模拟下差 3 倍（794.7 vs 244.0）。

## 三、实跑数字（`day70_result.json`，300 次重复 / 10 个种子）

### 3.1 反直觉一：UCB 照书抄，比贪心还差一倍

| 策略 | 平均 regret | 最差 10% | 冠军臂拉动 |
|---|---|---|---|
| 纯贪心（只热身一次） | 21.1 | 49.1 | 230 |
| ε-贪心 ε=0.1 | **13.7** | 27.8 | 314 |
| **UCB c=1（教材默认）** | **45.1** | 50.8 | 139 |
| UCB c=0.25 | 16.3 | 35.8 | 277 |
| Thompson | 22.6 | 36.2 | 241 |

**同一张表，两种读法**：

- 「UCB 很好」是**渐近命题**。400 炉里，$c=1$ 把 1/4 的炉次花在三流工艺上（单条轨迹里「先蒸后烤」被拉了 50 次、0.38 的「带杆密集烤」16 次）；
- ε-贪心看上去赢了（13.7 最低），但它对 ε 同样敏感——把 ε 从 0.1 改到 0.02 就立刻退回贪心水平。**这张表的正确结论不是「ε-贪心最好」，是「参数要先扫一遍」**。

### 3.2 反直觉二：冠军领先 8 个点还是 2 个点，决定了贪心会不会崩

把真值从「一个冠军（0.82 vs 0.74）」换成「三强贴身（0.82 / 0.74 / 0.72）」：

| | 一个冠军 | 三强贴身 |
|---|---|---|
| 纯贪心（只热身一次） | 21.1 | **22.8（且单条轨迹会押错）** |
| UCB c=0.25 | 16.3 | 18.2 |

单条轨迹里，「三强贴身」时**纯贪心 392 炉全押在 0.38 的「带杆密集烤」上**——
因为它第一次碰巧烤成了，然后**再也没有炉次去发现错误**。

> 结论写进教案的方式：**「要不要多试几次」不是算法问题，是「你以为的差距」和「你试过的次数」之比的问题**。
> 差距 8 个点时，一次观测就够；差距 2 个点时，一次观测不够。
> 论文里写「我们用了 UCB 算法，效果良好」没有信息量，要写「在 $\Delta p=0.02$、$T=400$ 时，UCB 的 c 取 0.25 才能把 regret 压在 20 炉以内」。

### 3.3 反直觉三：UCT 不会逼近最优，它逼近「规整解」

| 方法 | 成本（担·天） | gap |
|---|---|---|
| **精确 DP**（81 状态；2520 种全枚举核对） | **700.6** | — |
| 最短批优先 | 711.4 | +1.5% |
| 担数/时长比 | 713.0 | +1.8% |
| 最大批优先 | 819.4 | +17.0% |
| UCT 1000 次（访问最多选枝） | 428.7 | −38.8% |
| UCT 1000 次（均值最好选枝） | 287.7 | −58.9% |

**最优方案**：老周 → 德生 → 德生 → 老周 → 小陶 → 阿兰 → 阿兰 → 小陶。注意它**不是「一家连烘完」**，而是两家交错。

UCT 的模拟次数从 10 增加到 1000，成本**单调变差**（29.0 → 428.7）。深度一变，所有节点都在「从当前时刻重新计时」，
于是**越深越便宜**，搜索被那些「把剩余全塞给一户连着烘」的规整路径吸引。这不是种子噪声，是**系统偏差**——
所以本讲**不用中位数**（中位数会把少数成功放大），统一报「均值 / 最好 / 最差」三栏。

### 3.4 同样的搜索，换一个「读法」差 33%

同样 1000 次模拟：**「取访问最多的孩子」428.7 vs「取均值最好的孩子」287.7**。

UCT 经典实现取「访问最多」——在围棋里这是「最可靠的一手」；在本问题里它只是**被探索得最多**的一步。
「访问多」与「值好」在 $N$ 小时不是一回事（Day59 的老话：**别信单个值，要看它被验证了几次**）。

### 3.5 最该说出口的一句话：这题不该用 UCT

4 户 8 批 = **2520 种序列、81 个 DP 状态**。DP 用了不到 1 ms 就给出 700.6。
UCT 用了 1000 次模拟，还比最差的静态规则差 12%。

**算法选型的第一步不是「哪个高级」，而是「先量规模」**：
状态数能不能穷尽？不能，再多两个户（$3^6=729$）仍能穷尽；到 8 户（$3^8=6561$）也还是毫秒级。
真正需要 UCT 的是「分支大 + 深度到不了底 + 能自适应剪枝」的问题（AlphaGo 那类），
**不是这个「两维状态、一眼穷尽的排产」**。

### 3.6 敏感性：rollout 不是第一矛盾

300 次模拟下：规则 rollout 302.6，随机 rollout 295.1（差 2.5%，被种子方差吃掉）；
探索常数 c 从 0.1 扫到 5.0，均值 284.8~305.9，**全部落在「规整解」附近**——
**换 rollout、换 c 都改不了那个系统偏差，只有换算法（DP）才改得了。**

## 四、什么时候用哪一个

| 你手上的问题长什么样 | 用什么 |
|---|---|
| 有多个方案，效果要靠试才知道，试的次数有限 | **bandit**（UCB / Thompson）；先扫 c 或 ε |
| 每个方案的效果还取决于上下文（烟叶品质、客户等级） | 上下文 bandit（LinUCB），本讲未展开 |
| 结果的**随机性**来自已知分布，你要做序贯决策 | [[Day18 - 随机动态优化排队论MMc与MDP值迭代]] MDP 值迭代 / [[Day28 - 两阶段随机规划与样本均值近似SAA]] |
| 组合空间小到能 DP（状态 ≤ 几千） | **DP**（本讲的 81 状态），不要用搜索 |
| 组合空间大到 DP 装不下、但能快速模拟一条完整方案 | Monte Carlo 树搜索（本讲第二部分） |
| 组合空间大 + 结构复杂 + 有好的构造规则 | [[Day42 - 禁忌搜索与单机总加权延误排产]] / [[Day47 - 置换流水车间调度FSP_NEH构造与迭代贪心IG]] |

## 五、十个问（README 原则）

1. **谁在决策？** 烟叶站站长（工艺）+ 4 户烟农（谁家的先上炉）。
2. **决策是什么？** ① 每炉选一种工艺（在线学）；② 每炉烘谁家的哪一批。
3. **不做的代价？** 工艺选错 = 整炉降级；排错顺序 = 烟叶掉档，损耗 = 担数 × 等待天数。
4. **数据从哪来？** 工艺历史达标率（内部记录，本季不作数）、各户各批担数与烘制天数（收购台账）。全部硬编码在脚本头部。
5. **量化目标？** ① 累积 regret（相对全能者少收的达标炉数）；② 总加权等待（担·天）。
6. **可行域？** 每炉必选一种工艺；每家两批先后上、每次只烘一批、批不可中断。
7. **对照方案？** 贪心 / ε-贪心 / UCB(c=1, 0.25) / Thompson；三种静态规则 + UCT（两种选枝口径 × 5 个模拟量）。
8. **敏感什么？** 结构（冠军领先 8 点 vs 2 点）、UCB 的 c、UC T 的模拟量与选枝口径、rollout 设计。**结构变化的影响远大于参数**。
9. **结论对谁有用？** 站长（留几炉给新工艺）、调度员（先烘谁家的）、写论文的同学（什么时候可以不写「我们用了先进的 UCT」）。
10. **哪一步最可能错？** ① c 照抄 1；② rollout 从当前节点起算 / 跨深度比较模拟值；③ 用中位数掩盖系统偏差；
    ④ 在小规模问题上硬上 UCT，把 1.5% 的规则差距换成 40% 的搜索差距。

## 六、本讲的坑（返工 4 轮，全部实跑暴露）

1. **实例 0 教学点**：第一版 4 户批数 (2,2,2,2)、担数随机，最优就是「最短批优先」——整节课没有反转。
   → 把「老周第二批 30 担」「德生第一批 18 担」等量级拉开，最优解从「一家连烘」变成「两家交错」，教学点才立住。
2. **UCT 根节点被当成一条模拟**：`path=[root]`、根 N=1、子 N=1 同时出现，「访问最多」永远给第一个孩子 → 输出 0.0 担·天。
3. **深度变化时模拟值不能加总**：节点越深 t0 越大，值越小 → 搜索偏向深处。修法：rollout 返回「整条路径累计等待」。
4. **新节点从 `root.state` 派生**：同一批被排两次，序列长 6、成本 183（不可能的小数）。断言「序列长度 = 8」救回。
5. **「每步重建树」写法**：能跑，但每步都从零学，100 次模拟下 794.7（vs 244.0）。
6. **中位数骗人**：5 个种子的中位数 174，均值 244、最差 302.8。
7. **`json.dump` 遇 `np.float64` 崩**（Day66 家族），统一 `round(float(...), 3)`。
8. **中文图零告警**（Noto Sans CJK SC），`-W error` 全程 19.3 s。
