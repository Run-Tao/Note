## 一、这一课解决什么决策

某机加车间有一台**热处理炉**（瓶颈设备），一批 **9 个订单**排队等它处理，但炉子一次只能做一件、不能并行、不能抢单。每个订单有：

- **加工时间 $p_j$**（小时）；
- **承诺交期 $d_j$**（从开工起算，小时）—— 答应了客户必须交；
- **延误惩罚权重 $w_j$**（元/小时）—— 大客户、急件权重高。

炉子按某个**顺序 $\sigma$** 一件件做，第 $j$ 件做完的时刻记 $C_j$，延误 $T_j=\max(0,\,C_j-d_j)$。

> **决策问题：给这 9 个订单找一个加工顺序 $\sigma$，使「总加权延误」最小**
> $$\min_{\sigma}\ \sum_{j} w_j\,T_j\,.$$
> 这就是单机调度里最经典的难题之一：**$1\,\|\, \sum w_j T_j$**。

**为什么不能拍脑袋、也不能贪心？** 交期最早优先（EDD）看着合理，但它只看交期、不看惩罚权重；加权最短优先（WSPT）只看权重和工时、不看交期。真实矛盾在于：**权重大的订单往往加工时间长，早做它会拖累后面一堆小订单**。三者互相拉扯，$1\,\|\,\sum w_jT_j$ 早在 1977 年就被 Lawler 证明是**强 NP-hard**——没有多项式精确算法，规模一大连最优都算不出来，只能靠**邻域搜索 / 元启发式**在可接受时间里找好解。

## 二、10 问逐条回答

### 1. 解决什么问题？
在**一台瓶颈设备 + 一批带交期和惩罚的订单**里决定加工顺序，使**总加权延误最小**。它是「车间排产 / 单机调度 / 任务排序」类赛题的核心：热处理炉排单、单条产线排产、单窗口办件排序、单服务器任务调度……凡「一件一件做、有交期、晚了要罚」都是它。

### 2. 什么情况下使用？
- 有**明确的先后排列**决策（谁先谁后），目标是**延误/超期相关**的惩罚；
- 问题**规模不小、NP-hard**，精确算法（分支定界 / 全排列）算不动；
- 需要**在可接受时间内给出「足够好」的解**，并且能**用规则解做起点**。
这时标准武器就是**邻域搜索**：从一个排产顺序出发，做**小改动**（交换两件的位置），一步步改进。

### 3. 它和已有方法什么关系？
- **精确法**（Day4 分支定界 / Day16 DP / 本课暴力枚举）：小规模能拿**真最优**，本课用它当**裁判**；规模一大就爆。
- **构造规则**（EDD / WSPT / ATC）：**秒出**一个还行的解，但**易被局部结构困住**（本课 ATC 距最优 +51%）。
- **随机性元启发式**（Day6 遗传 GA / 模拟退火 SA）：靠**随机扰动**跳坑，方向不明。
- **禁忌搜索（本课）**：**确定性**的邻域搜索——每一步在邻域里挑**最优允许移动**，哪怕它是**变差的移动**，用**禁忌表**防止原地打转，用**特赦准则**破禁，用**重启**做多样化。**它是「有记忆的爬山」**。

### 4. 核心思想是什么（一句话）？
> **爬山法为什么卡住？因为它只肯走"下坡"（改进）方向，一到局部最低点，四面都是上坡，它就"看不见"路了。**
> **禁忌搜索的破法：允许走"上坡"（变差）方向！** 但为了防止马上又滑回刚才那个坑，**用一张禁忌表把"刚走过的移动"暂时封禁**。于是搜索被"逼着"探索新区域，反而有机会绕到更高（更优）的山谷。

### 5. 关键机制有哪几件？

**(a) 邻域（Neighborhood）——"小改动"是什么？**
本课用**交换邻域**：任取两个位置 $i<j$，交换这两件订单，得到一个新顺序。一个排列有 $\binom{n}{2}$ 个邻居（$n=9$ 时 36 个）。

**(b) 移动与"最优允许移动"**
每一轮遍历**全部邻居**，选出**目标值最优**的那一个移动——**注意：哪怕它比当前解更差，也照走**。这就是逃出局部最优的关键。

**(c) 禁忌表（Tabu List）——"不许立刻走回头路"**
把最近做过的移动（本课用「交换了哪两件订单」作禁忌键）记进表，在**禁忌期限 $T$** 内禁止再用。防止「交换 A、B」后下一步立刻「交换 B、A」又滑回去。**禁忌期限 $T$ 是超参数**：太小 → 循环打转；太大 → 过度限制、搜不动。

**(d) 特赦准则（Aspiration Criterion）——"实在太香就破例"**
如果某个移动**虽然被禁忌，但能刷新冠军解**，就破禁允许它——以免好解被白白锁死。

**(e) 停滞重启（Restart / Diversification）——"太久没进步就换个地方"**
若连续 $R$ 轮没改进，就**从当前冠军解出发做随机扰动**重新出发（保留精英），进一步多样化。

### 6. 为什么这样设计能奏效？
- **允许变差移动** → 能翻过局部最优的「山脊」，这是爬山永远做不到的；
- **禁忌表 + 期限** → 防止在同一个局部坑边缘**来回抖动（cycling）**，把搜索力导向新区域；
- **特赦准则** → 补偿禁忌表可能误伤好移动的风险；
- **重启** → 万一整个区域都挖空了，换个盆地再挖。
三者合起来 = **「探索（走坏棋）」与「开发（挑最优）的动态平衡」**，正是所有元启发式的灵魂。

### 7. 怎么建模？（10 问的建模部分）
```
参数: p_j(工时)  d_j(交期)  w_j(惩罚权重)
决策: 一个排列 σ = (σ_1,...,σ_n)          # 订单的加工先后
中间量: C_k = Σ_{i<=k} p_{σ_i}            # 第 k 位订单的完工时刻
        T_k = max(0, C_k - d_{σ_k})       # 其延误
目标:   min Σ_k w_{σ_k} · T_k             # 总加权延误
```
目标函数对 $\sigma$ 是**非凸、非光滑、有大量局部最优**的分段函数——这正是贪心/爬山会栽的地方。

### 8. 算法链路（本课代码全手写，零调度库）
1. **构造规则**出初始解：EDD / WSPT / **ATC**（Apparent Tardiness Cost，交期型排产里通常优于前两者）；
2. **禁忌搜索主循环**：遍历交换邻域 → 选**最优允许移动**（禁忌或特赦）→ 更新禁忌表 → 更新冠军解；
3. **停滞重启**：连续 $R$ 轮无改进 → 从冠军解扰动重启；
4. **对照**：爬山法（只走改进）、随机重启局部搜索；
5. **独立裁判**：**暴力枚举全部 $n!$ 个排列**求真最优（仅小 $n$ 可用）；
6. **鲁棒性**：20 个随机实例上禁忌搜索 vs 暴力真最优交叉验证。

### 9. 结果怎么读？（实跑，`.venv` 跑通）

实例：$n=9$，$p=[20,11,29,28,6,9,9,9,19]$，$d=[57,95,90,35,68,72,67,42,85]$，$w=[4,5,3,9,7,6,2,2,9]$，总工时 140h。

| 方法 | 总加权延误 ΣwT | 距真最优 |
|---|---|---|
| 暴力枚举（**真最优**） | **327** | — |
| EDD 规则 | 559 | **+71%** |
| WSPT 规则 | 836 | **+156%** |
| ATC 规则 | 494 | **+51%** |
| **爬山法**（ATC 起点） | **366** | **+11.9%（卡在局部最优！）** |
| 随机重启局部搜索（200 次） | 327 | 0% |
| **禁忌搜索（本课）** | **327** | **0% ✅** |

- **读法**：规则解离最优很远（ATC 也差 51%），说明这题**不是"选对规则"能解决的**；
- **爬山法栽在 366**——只走改进方向，**11.9% 的差距就是它翻不过去那道山脊的代价**，这是本课最核心的教学点；
- **禁忌搜索（0.38 秒）一步不差到达真最优 327**，与暴力枚举（5.3 秒）**完全一致**；
- 禁忌搜索和随机重启这次都达到最优——说明**禁忌搜索的价值在于"确定性 + 更快/更省算力"**，它不需要像随机重启那样靠运气重复 200 次。

最优顺序：`[3, 7, 0, 4, 5, 8, 1, 6, 2]`。

### 10. 交付物与迁移面？
- **交付物**：一份**最优加工顺序 + 总加权延误 + 「爬山法会比最优多罚多少」的量化证据**，外加一个**经暴力核验过的禁忌搜索工具**。
- **迁移面**：凡「**排列/顺序**决策 + **带权重目标** + **NP-hard**」皆可套——车间排产、TSP/VRP（Day6/21）、作业调度、课表编排、基因排序、装箱顺序……
- **一句话带走**：**当爬山卡住时，禁忌搜索教你"主动走几步坏棋，但记住别马上原路返回"。**

## 三、四张图怎么看（`tabu_search_scheduling.png`）

1. **左上 · 收敛轨迹**：灰线=当前解（会上下波动，因为在走"坏棋"），红线=历史最优（阶梯式下探），绿虚线=暴力真最优参照。红线下探到绿线 = 搜到最优。
2. **右上 · 七法对比柱状**：EDD/WSPT/ATC（规则）高、爬山法次之、禁忌搜索=随机重启=暴力（最优）。**爬山法与最优之间的高度差 = "局部最优陷阱"的代价**。
3. **左下 · 甘特图**：最优顺序的排产条（红=延误、绿=准时），蓝刻度=各订单交期。能一眼看出"红条为什么红、蓝线为什么没赶上"。
4. **右下 · 延误明细**：各订单对总目标的加权延误贡献，定位"谁在拖后腿"。

## 四、避坑记录（写给自己 & 后来者）

1. **教学实例必须让爬山法真吃亏**：第一版用 `n=10, seed=7`，ATC 与爬山**恰好都到最优（210）**，"爬山会卡住"这个核心教学点直接落空。切换到 `n=9, seed=12` 后爬山停在 366（**+11.9%**）、ATC 差 51%，教学链条才立起来——**教学数据要刻意设计以暴露算法行为**（与 Day22/24/25/26/31/33/34/35/36/37/38/39/40/41 同一教训，已第 N 次复现）。
2. **暴力枚举要用向量化**：`itertools.permutations` + 逐点循环对 $n=10$ 要 50 秒；改用 `np.cumsum` 向量化后 $n=9$ 只需 5 秒——**裁判也要跑得动**。
3. **裁判返回值别写反**：`brute_force` 返回 `(最优值, 最优顺序)`，鲁棒性循环里若按 `(_order, val)` 解包，`val` 会变成 list、`tval - bval` 直接报 `unsupported operand type(s)`。**函数返回值顺序要在调用处一眼可核**。
4. **禁忌表的"键"要对称**：交换 $(i,j)$ 与 $(j,i)$ 是**同一个移动**，禁忌键必须 `tuple(sorted((...)))` 规整，否则禁令形同虚设。
5. **禁忌期限不能拍一个数就完事**：太小 → 循环、太大 → 僵死；本课每个键的解禁时刻还加了随机抖动（`it + randint(1,T)`），避免所有键同时解禁、步调一致地打转。
6. **特赦准则不能漏**：没有它，被禁忌的好移动会被白白锁死，冠军解可能永远达不到——本课实现 `is_tabu and val >= best_val: skip`。
7. **图里的数学下标要投字体所好**：`ΣwⱼTⱼ` 里的 **`ⱼ`（U+2C7C）在 Noto Sans CJK SC 里缺失**，会触发 `Glyph missing` 告警。改用 `w_j·T_j` 后干净通过——**中文图里的特殊 Unicode 下标符号要么换成 ASCII，要么确认字体覆盖**。
8. **图输出路径用 `__file__` 锚定**（参照 Day36–41），从任意 cwd 运行都能正确落图。
