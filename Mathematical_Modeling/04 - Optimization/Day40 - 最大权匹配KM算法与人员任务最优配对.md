## 一、这一课解决什么决策

前面两讲我们把「配对」问题的**结构**讲透了：二分图用匈牙利（Day22）、一般图用带花树（Day39）。
但它们解决的都只是——**「能不能配上、最多配几对」**（最大**基数**匹配）。

现实里的配对，几乎从不满足于「配上就行」：

> **某咨询公司接到 6 个项目，要派 6 名顾问各自认领 1 个（一人一项、一项一人）。
> 每个顾问做每个项目的预期创收不同（有的拿手、有的勉强）。怎么派，总创收最大？**

这就是**最大权匹配（Maximum Weight Matching）**问题，在二分图上它就是经典的**指派问题（Assignment Problem）**。
注意它和 Day22 的区别：

- Day22 的匈牙利解的是「**能配几对**」（每条边权重都是 1，只需最大基数）；
- 今天要解的是「**配得多值钱**」（每条边有真实的收益/成本 $w_{ij}$，要最大化总权重）。

**决策变量**：$x_{ij}\in\{0,1\}$，表示第 $i$ 名顾问是否认领第 $j$ 个项目。

**模型（指派问题 / 完美匹配）**：

$$
\max\ \sum_{i=1}^{n}\sum_{j=1}^{n} w_{ij}\,x_{ij}
\quad\text{s.t.}\quad
\sum_{j=1}^{n} x_{ij}=1\ \ \forall i,\qquad
\sum_{i=1}^{n} x_{ij}=1\ \ \forall j,\qquad
x_{ij}\in\{0,1\}.
$$

## 二、为什么要开一个新算法：贪心为什么不行

新手第一反应是**贪心**：「每次挑当前最大的收益，把对应的人和项目划掉」。本课代码里专门做了贪心对照，
它给出了一个**看起来很合理、实则会亏钱**的方案：

- 若最高收益那一格一旦被占用，就再也没有补救机会。
- 贪心**只顾眼前一步**，不会「退回重来」。本例中贪心总收益明显低于最优。

那能不能用 Day22 的匈牙利算法？**不能直接套**——匈牙利法解的是「每条边等权」的基数匹配，
它找的是「尽量多的配对」，而不是「总权重最大的配对」。权重一进来，
增广路的判据就从「有没有边」变成「**改变配对到底赚不赚**」。

## 三、KM 算法的灵魂：把权值变成对偶价，让每步增广都稳赚（10 问之 3、4、5）

**Kuhn–Munkres（KM）算法**（也叫匈牙利法的加权版）的巧妙之处，在于它**死死抱住 [[Day26 - 线性规划对偶理论影子价格与敏感性分析|LP 对偶]]**：

为每个人 $i$ 引入一个**行势** $u_i$，为每个项目 $j$ 引入一个**列势** $v_j$，满足**可行性约束**：

$$
u_i + v_j \ge w_{ij}\qquad \forall i,j.
$$

（这条正是「对偶可行」：势不能低于任何一格的权重。）记**松紧** $slack_{ij}=w_{ij}-u_i-v_j\le 0$ 的那一格为**紧边**（取等号）。

**KM 的三个要点**，正好回答建模者最想问的问题：

1. **为什么盯着「紧边」找增广路？**
   在只由紧边构成的「相等子图」里做匹配，`∑ 势 = ∑ 被匹配边的权重`（紧边上 $u_i+v_j=w_{ij}$）。
   于是一旦在相等子图里找到**完美匹配**，由 $u_i+v_j\ge w_{ij}$ 立刻推出这组匹配就是全局最优
   ——这就是对偶的**弱对偶定理**：任何匹配权重 $\le$ 任何势之和，相等即最优。

2. **找不到完美匹配时怎么办？**
   给所有「搜索树上的人」的势 $u_i$ **加** $\delta$、所有「搜索树上的项目」的势 $v_j$ **减** $\delta$，
   其中 $\delta=\min\{u_i+v_j-w_{ij}\}$（当前最「松」的那条边的松弛量）。
   这一**对偶修正**让每条候选边的松弛量整体变化，正好**把至少一条松边推成紧边**，
   于是相等子图增大、搜索树能继续长——直到出现完美匹配。

3. **为什么这样调不亏？** 势的调整**始终维持 $u_i+v_j\ge w_{ij}$**（对偶可行），
   所以最终匹配的权重始终被势之和从上方夹住，收敛时上下界贴合 → 最优。

一句话：**KM 把「人—项目收益表」翻译成一组对偶价，用「调价」代替「试错」，每步都保持对偶可行，
匹配一完美就自动最优。** 复杂度 $O(n^3)$——和 Day22 的匈牙利同阶，只是多了一层权重与势。

## 四、求解与验证（10 问之 6、7）

代码（`08 - Python/daily/2026-10-09/kuhn_munkres_weighted_matching.py`）**零专用指派求解器**，全部手写：

- 手写 **KM 算法**（行势/列势初始化 → 对每个未匹配行 BFS 找增广路 → 逐步收紧势 $\delta$ → 匹配数递增）；
- **暴力枚举 $n!$** 作**独立裁判**（$n=6$ 时仅 720 种排列，可穷举出真最优）；
- **贪心对照**（暴露「只顾眼前必亏」）；
- **可行性核验**：一人一项、一项一人、每份收益都真实存在。

## 五、关键运行结果（`.venv` 实跑）

```
顾问 6 名 / 项目 6 个，收益矩阵 6×6

[KM 算法] 最优总收益 = 456.0
    顾问 0 → 项目 2（收益 79）
    顾问 1 → 项目 3（收益 70）
    顾问 2 → 项目 0（收益 84）
    顾问 3 → 项目 5（收益 83）
    顾问 4 → 项目 4（收益 63）
    顾问 5 → 项目 1（收益 77）
[暴力枚举裁判] 最优总收益 = 456.0   # 与 KM 完全一致
[贪心对照] 总收益 = 344.0（比最优少 112，−24.6%）
```

**⭐ KM == 暴力真最优 456.0；贪心只有 344.0，少赚 112（−24.6%）。**

本例刻意把「顾问 3 在项目 0 上的收益 87」设成全局最高格——
**贪心会先抢这一格**，但它同时锁死了「顾问 0 / 顾问 2」这两位在项目 0 上也很强的顾问，
于是后续只能拿次优搭配，总收益掉到 344。**KM 会「忍痛让掉」这一格，换回全局最优 456。**
这正是「局部最优 ≠ 全局最优」最直观的教材。

## 六、要点与迁移（10 问之 8、9、10）

- **「最大权匹配」= 派活 / 分任务 / 排班 / 一对一撮合的最优版**：只要你能写出
  「人对事的价值表」$w_{ij}$，KM 就能给出**总价值最大**的一对一方案；
- **它和 Day22/39 是一条线上的三个台阶**：
  **最大基数匹配（只看能不能配，Day22 二分图 / Day39 一般图）→ 最大权匹配（看配得多值钱，本课二分图 / 权重版 Blossom 一般图）**；
- **它的理论根基是对偶**——势 $u_i,v_j$ 就是 [[Day26 - 线性规划对偶理论影子价格与敏感性分析|影子价格]]，
  KM 的「调价」就是在**维护对偶可行**、用对偶界夹住原问题；
- **贪心是陷阱**：局部最优的总和不是全局最优，这正是「组合优化需要算法、不能拍脑袋」的最好例子；
- **写进论文**：写出指派模型 → 说明为何需要加权匹配（不是基数匹配）→ 给出 KM 或
  MILP 求解 → 用暴力/对偶核验 → 报告「贪心 vs 最优的差距」作为算法价值证据。
