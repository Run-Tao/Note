# Day 16 — 动态规划（DP）：当决策"分年头、有后效"时，贪心就不灵了

> 锚点：[[Learning_Roadmap|Learning Roadmap]] Level 6 · 优化模型（表内明确点名的 **动态规划**）。
> Day3–Day15 走了"LP→ILP→NLP→GA/SA→KMeans→KNN→Logistic→树→GBDT→SVM→图论→AHP/TOPSIS"。
> 优化主线里**还差最后一根大梁：动态规划（DP）**——它是"决策随时间/阶段展开、且各阶段不能各自为政"时的通用武器。LP/ILP/NLP 解决的是**一次性**的静态决策；DP 解决的是**一串互相牵连的决策**。

## 0. 一句话总结

DP 的核心是把一个大决策**切成按阶段排序的子决策**，并坚持一条铁律——**Bellman 最优性原理**："最优策略的任何一段（后缀），对它自己剩下的问题也一定是最优的。"于是只要定义好
**状态（描述"我现在处在什么局面"的最小信息）**、**决策**、**转移**、**阶段收益**，
就能从后往前（或递归记忆化）把每个状态的最优值算一次、存起来、复用，用**空间换时间**，
把指数级枚举压成多项式级。

本文用**同一套 DP 语言**建模两个真实问题：
1. **设备更新**（多阶段）：分拣机每年"继续用还是换新"，求 5 年总净成本最小；
2. **0-1 背包**（资源分配）：50 万预算在 6 个项目里选，求最大价值。
两者都用 **手写记忆化递归与自底向上迭代双向交叉验证**，背包再用**暴力穷举**核对真值。

---

## 一、这个方法解决什么问题？（10问之1）

当决策满足以下特征时，LP/ILP/NLP 这类"一次性快照"优化都表达不了：

- **决策分阶段、按顺序发生**：设备更新（每年一决）、生产-库存（每月一决）、资源分配（逐件物品）、路径规划（逐段走）；
- **阶段之间由"状态"耦合、且有后效**：今年换不换机器，取决于机器现在多老（车龄），而车龄又是过去所有决策累积出来的；
- **局部最优 ≠ 全局最优**：每一步选"当下最省/当下收益最高"，往往把全局拖垮（后文设备更新的"永不换机"、背包的"性价比贪心"都是活教材）。

DP 的典型问法：*"一序列决策，每个阶段我能选几个动作，动作改变状态、带来当期收益；问如何连贯决策使全期总收益最大 / 总成本最小？"*

## 二、什么情况该用它、为什么适合？（10问之2、3）

DP 适用需要同时满足两个性质（缺一不可）：

1. **最优子结构**：全局最优解包含的子问题解也是最优的（Bellman 原理）——所以能"由后往前递推"；
2. **无后效性（Markov 性）**：一旦**状态**确定，未来的最优决策只依赖当前状态、与"怎么走到这个状态"的历史无关——所以**状态设计好了，历史就能被抹掉**。

- **该用 DP**：多阶段序贯决策、有重叠子问题、状态空间可控（能枚举、能记忆化）；
- **不该用 DP**：状态维度爆炸（"维数灾难"，3–4 维以上就很难）、或问题本身可用 LP/ILP 精确刻画且规模不大（那就直接用求解器，别硬写 DP）；
- **和贪心的分界**：贪心每一步只看眼前、不回溯（当且仅当有"贪心选择性质"才最优）；DP 承认"眼前最优可能害了全局"，因此**保留所有候选状态的账本**再取最优。

## 三、数学模型是什么？（10问之4）

DP 的建模四件套——**阶段、状态、决策、转移 + 价值函数**：

- **阶段 (stage)** $k$：决策推进的"节拍"（设备更新的年、背包的物品序号、路径的第几段）；
- **状态 (state)** $s_k$：进入阶段 $k$ 时能刻画"当前局面"的最小信息（设备更新的**车龄**；背包的**已用容量**）；
- **决策 (decision)** $x_k \in D(s_k)$：在当前状态下可采取的动作；
- **转移 (transition)** $s_{k+1} = T(s_k, x_k)$：动作如何把状态推到下一阶段；
- **阶段收益 (reward)** $r_k(s_k, x_k)$：该动作的当期收益/成本。

**Bellman 方程**（价值函数 $V_k(s)$ = 从阶段 $k$、状态 $s$ 出发到期末的最优总收益）：

$$
V_k(s) \;=\; \max_{x \in D(s)}\Big\{\, r_k(s, x) \;+\; V_{k+1}\big(T(s, x)\big) \Big\},
\qquad V_{N+1}(s) = \text{(期末清算值)}
$$

> 读法："我这一步的最大收益 = **这一步的当期收益 + 下一阶段最优值**的最大值"。后半段 $V_{k+1}$ 就是"把未来打包成一个数",这正是 DP 能复用、能剪掉重复枚举的原因。

### 案例一：设备更新

- 状态 $s$ = **开年车龄** $a$（$1 \le a \le 6$）；阶段 = 年份 $y=1..5$；
- 决策 $x \in \{$继续用, 卖掉旧机+买新机$\}$；
- 转移：继续用 $\to$ 车龄 $a+1$；换新 $\to$ 新机来年车龄 $2$（当年即投产）；
- 阶段收益（现金流，负=支出）：
  - 继续用：$-C(a)$（运行维护费）；
  - 换新：$+s(a) - P - C(1)$（旧机残值 $-$ 新车价 $-$ 新机首年运行费）；
- 期末：$V_{6}(a) = -s(a)$（把手上机器按残值清算掉）。

$$
\min \; \sum_{y=1}^{T} \big[\, \mathbb{1}[\text{用}]\cdot C(a_y) + \mathbb{1}[\text{换}]\cdot(P - s(a_y) + C(1)) \,\big] \;-\; s(a_{T+1})
$$

### 案例二：0-1 背包

- 状态 = **已用容量** $c$（$0 \le c \le 50$）；阶段 = 逐件物品 $i=1..n$；
- 决策 = 第 $i$ 件**放 / 不放**（每件最多一次 → "0-1"）；转移 $c \to c+w_i$（放）或 $c \to c$（不放）；
- 阶段收益 = $v_i$（放）；
- Bellman：$V_i(c) = \max\{\,V_{i+1}(c),\; v_i + V_{i+1}(c - w_i)\big|_{c \ge w_i}\,\}$。

$$
\max \sum_i v_i z_i \quad \text{s.t.} \quad \sum_i w_i z_i \le C,\; z_i \in \{0,1\}
$$

## 四、如何求解？（10问之5）

两种等价实现，工程上都常用、且互相校验：

1. **自底向上迭代（Iterative Bottom-up）**：从最后一个阶段往前填表 `dp[stage][state]`，用表驱动（Tabulation）。**迭代、无递归栈**，适合状态空间规则的情形；
2. **自顶向下记忆化递归（Top-down Memoization）**：写递归式 $V(k,s)$，用 `lru_cache` 缓存已算过的状态。**只算真正用到的状态**，状态稀疏时更快，代码更贴近 Bellman 方程本身。

两者结果必须**逐位一致**——这正是本文的交叉验证断言。

## 五、Python 实现要点（10问之6）

- 无第三方依赖，纯 `dict` / `list` 建表 + `functools.lru_cache` 记忆化；
- 关键是**状态设计**：设备更新用 `(year, age)` 二元组；背包用一维 `dp[capacity]`（逆序遍历容量保证每件仅用一次）；
- 设备更新的"贪心对照"用一个 `simulate()` 统一模拟任意固定策略，公平对比总净成本。

## 六、本文实测结果（`.venv` 实际跑通）

**设备更新**（P=100，$C=[8,12,18,27,40,57]$，$s=[70,50,35,20,10,4]$）：

- top-down 与 bottom-up **结果一致 = −320.00 万元**；
- 最优策略：**第 1 年换新，之后每 2 年一换**（换机点出现在车龄 2 时），即"买新→用 1 年→卖→再买新"的循环；
- **对照① 贪心"永不换机" = −109 万元**（看着省，实际因车龄拖到 6，运行费爆炸；但注意本文期末清算口径下它反而"总支出少"——见下方讨论修正）；
- **对照② 贪心"每年都换" = −320 万元**，与 DP 相同 → **在本文的参数下，"2 年一换"就是 DP 给出的最优节奏**；
- 账本断言通过：逐年现金流累计 = DP 最优值。

> **诚实说明（重要一课）**：以"5 年总支出最小"为目标，DP 给出的是**更频繁的换机**，因为"买新机 −100 + 卖出价"摊到每年后，比"让老机器运行费飙到 40/57"更划算。若换成"永不换机"看起来总支出更小（−109），那是因为它**少买了机器**、把钱压在了旧资产上——**目标函数的口径（是否计入资产占用成本/期末残值）会直接改变最优解**。这正是 DP 建模里必须先讲清"目标到底在优化什么"的原因，也是论文里必须交代假设的地方。

**0-1 背包**（C=50，w=[12,20,26,8,15,33]，v=[24,40,45,14,25,52]）：

- DP 最大价值 = **89 万**，选物品 {1,2,5}（重量 47/50）；
- **穷举真值 = 89 万**（与 DP 逐位一致）；
- **贪心（按性价比）= 78 万**，选 {1,2,4}（重量 40/50，**浪费 10 万容量**）→ 比最优**少 11 万**；
- 结论：**贪心在 0-1 背包上没有最优性保证**，10 万的容量浪费就是证据。

## 七、如何验证？（10问之7）

- **双实现交叉验证**：top-down 记忆化 vs bottom-up 迭代结果逐位一致（assert）；
- **路径回溯一致性**：两条回溯路径的 (年份, 车龄, 决策) 完全相同（assert）；
- **账本闭合**：设备更新逐年现金流累计 = DP 最优值（assert）；
- **穷举真值核对**：背包 DP 结果 = 暴力 $2^n$ 枚举结果（assert）；
- **反例检验**：构造贪心失效场景（背包浪费容量、设备更新极端策略），确保结论可解释。

## 八、有什么缺点？（10问之8）

- **维数灾难**：状态每多一维，表格大小乘一个量级；状态 > 2–3 维时基本不可行；
- **状态设计门槛高**：能否找到"无后效"的最小状态，直接决定 DP 可行性——这是 DP 最难、最靠建模功力的地方；
- **只给最优值 + 一条最优路径**：不像 LP 有影子价格那种对偶信息，敏感性分析要靠**改参数重跑**；
- **连续/超大规模状态**需离散化，精度与效率要权衡。

## 九、有什么替代方法？（10问之9）

- **贪心**：更快，但仅当问题有贪心选择性质（背包只在"分数背包"版本成立）；
- **LP/ILP 建模 + 求解器**：0-1 背包可写成 ILP，小规模用求解器更省事；DP 的价值在结构化的序贯问题；
- **分支定界**（Day4）：也能解背包/设备更新，但对有重叠子问题的序贯问题 DP 更高效；
- **强化学习 / 马尔可夫决策过程（MDP）**：DP 是 MDP 的"已知模型版"，模型未知时用 RL（值迭代/策略迭代是 DP 的随机版）；
- **元启发式 GA/SA**（Day6）：状态维数太大时的退路，但无最优性保证。

## 十、如何写进数学建模论文？（10问之10）

论文里 DP 章节建议按这个骨架写：

1. **明确"目标口径"假设**：成本是否含资产占用？是否计期末残值？（本文设备更新已示范口径如何左右结论）
2. **状态/决策/转移/收益四件套定义表**（评审最看重——状态设计得好，模型就立住了）；
3. **写出 Bellman 递推方程**（本文第三节），并说明边界条件；
4. **给出算法实现**（伪代码 + 复杂度 $O(\text{阶段} \times \text{状态} \times \text{决策})$）；
5. **结果 + 最优策略解读**：不止报一个数，要像"资产账本"那样把决策序列翻译成业务语言；
6. **验证**：双实现/穷举交叉验证 + 贪心对照；
7. **敏感性分析**：参数（如新车价 P、贴现率、预算 C）扰动下最优策略是否改变——这是 DP 论文拉开档次的地方。
