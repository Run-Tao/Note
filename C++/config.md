# config.md — 知识库规范

> 本文件是整个 C++ 知识库的**规范权威来源**：长期目标与写作规范都定义在这里。
>
> **适用范围**：`C++/` 下所有 Markdown 文件（现有及以后新增）。
> **维护原则**：维护知识库时（新建笔记、练习、代码、资源条目、回答学习问题）默认遵守本文件；如内容有冲突，以本文件为准。

## 1. 学习者背景

- 目标读者：面向人工智能 / 计算机方向的本科生，按此标准学习和写作；
- 编程起点：具备基础编程概念（变量、循环、函数），C++ 从零系统学习；
- 语言标准：以 **现代 C++（C++17 / C++20）** 为准，尽量使用标准库与惯用法，除非讲历史或对比，不教 C 风格写法；
- 学习心态：理解优先于记忆，先搞清"为什么这样设计 / 代价是什么"，再记语法；
- 使用环境：Obsidian 笔记库（Markdown）+ 本地编译器（g++ / clang++ / MSVC），笔记要可复读、可检索、可迭代。

## 2. 学习目标

1. **理解语言模型**：能解释类型系统、对象生命周期、内存布局、值语义与引用语义；
2. **写正确的代码**：理解未定义行为，避免悬垂指针、内存泄漏、数据竞争；
3. **写清晰的代码**：善用 RAII、`const`、标准库，代码可读、可维护；
4. **可维护**：笔记经过自己的话重组，标注来源与日期，允许半年后回看仍然读得懂且有可运行代码。

**单个 Level 的完成标准**：

- 能用一两句话讲清该 Level 的核心概念与设计动机；
- 能独立完成配套练习，并写出可编译运行、无警告的代码；
- 能在真实场景（算法题、小项目、AI 工程）中找到至少一个应用示例并写进笔记。

## 3. 写作要求

- 使用 Markdown，中文为主；术语首次出现时保留英文原名（如 左值 lvalue、移动语义 move semantics）；
- 一主题一文件，文件名简洁清晰，例如 `Notes/Level4_Memory_and_Pointers.md`；
- 代码块标注语言 ` ```cpp `；示例代码应完整可编译，避免伪代码式片段；
- 每篇笔记记录日期与来源（书籍 / 课程 / 文档 + 链接），便于回溯；
- 禁止大段照抄教材或文档，必须用自己的话重组；
- 学习过程中的疑问在笔记中用 `> [!question] 未解决` 标记，不积压在正文里；
- **代码规范**：变量 / 函数命名清晰，示范代码尽量遵守现代 C++ 惯例；涉及性能的结论要标注编译选项与环境。

**笔记模板**（每篇笔记按此结构组织）

```markdown
# 主题名

## 直觉
（为什么需要它、解决什么问题、心智模型）

## 语法与规则
（关键语法、语义、示例代码）

## 示例
（可编译运行的完整示例，含输出 / 说明）

## 常见陷阱与 UB
（容易写错的地方、未定义行为、编译器差异）

## 性能与代价
（时间 / 空间、编译期 vs 运行期、可能的优化）

## 应用
（在算法、系统、AI 工程中的真实用途）

## 遗留疑问
> [!question] 未解决
```

## 4. 修改文件的原则

- **增量修改**：不删除正确内容、不无理由重写、不改变已有知识结构；
- 错误可修正，但保留结构、链接与 Wiki Links；
- 重命名 / 移动文件前，先检查并更新所有引用它的 Wiki Links；
- 修改 config.md 等规范文件属于重大变更：先说明理由，再同步更新 README 与相关模板。

## 5. 不重复已有知识

- 动手前先搜索 / 阅读相关笔记，确认内容是否已存在；
- 已有内容直接引用（Wiki Link），不重复写入；
- 新内容只写"已有笔记之外"的部分，避免产生内容重叠的文件。

## 6. 不随意修改无关文件

- 每次任务只触碰与任务直接相关的文件；
- 不清理、不重排、不"顺手优化"无关目录；
- 归属不明确的内容先记录到 Inbox/ 或询问，不擅自移动或删除。

## 7. 参考阅读资料的下载

- 生成参考阅读资料（标准文档、教程、PDF、网页等）时，凡可下载的文档一律**下载到 `Resources/Downloads/`**，而不只在笔记里留链接；
- 下载规则：文件名清晰（`作者 - 标题.pdf` 或 `标题.pdf`），避免无意义文件名；网页可保存为 Markdown / PDF；
- 下载后：① 在 [Resources/README.md](Resources/README.md) 的索引中登记（名称、难度、语言、推荐理由、本地路径）；② 在笔记中用 Wiki Link 或相对路径引用本地文件，而不是外链；
- 无法下载 / 仅限在线浏览的（如视频、需登录的资源）才只记录链接，并标注"仅在线"；
- 下载位置只限 `Resources/Downloads/`，不散落在其他目录。

## 8. 代码与笔记的关系

- 大段完整代码放 `Code/`（可编译运行），笔记中只保留关键片段与结论；
- 每个 `Code/` 子目录是独立可编译单元，应包含说明（`README.md`）与构建方式（如 `CMakeLists.txt` 或注释中的编译命令）；
- 推荐统一使用：`g++ -std=c++20 -Wall -Wextra -O2`（Windows 上可用 MSVC 或 MinGW）。

## 9. 输出长度控制

- 优先完成文件修改，而非长篇聊天解释；
- 回复简洁：说清"做了什么、改了哪些文件、下一步是什么"即可；
- 写入文件的内容同样克制：只写必要信息，不堆砌已有内容；
- 需要长内容时写入文件，不在对话里展开。
