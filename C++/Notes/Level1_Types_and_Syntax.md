# Level 1 类型与基础语法

> 程序处理的一切都是"值"，而每个值都必须先有**类型**。类型决定了编译器如何解释内存中的一段二进制。
> 本章整理：变量与数据类型、定义与命名、初始化、整型的机器表示、枚举。

## 直觉

计算机内存是一大片可以操作的存储空间。**变量就是给其中一块空间起的名字**；**类型决定这块空间的大小、布局、可取值范围以及能参与的运算**。

先有类型，编译器才知道"这段内存里放的是什么、能对它做什么"——这也是 C++ 作为静态类型语言与 Python 等动态类型语言的根本区别。

## 1. 变量与数据类型

> [!note] 我的原始理解（未验证）
> - 变量：提供同一个具体的、可供程序操作的存储空间（内存中）
> - C++ 的每个变量都有其数据类型；数据类型决定着变量占内存空间的大小和布局方式、该空间能存储的值的范围，以及变量能参与的运算
> - 变量有三个重要属性：数据类型、名称、值

- **变量（variable）**：内存中一块被命名的存储空间；
- **类型（type）**决定四件事：
  1. 占用的内存大小（字节数）；
  2. 内存布局方式（如何编码）；
  3. 能表示的值的范围；
  4. 能参与的运算（如 `int` 做整除，`double` 做浮点运算）。
- 变量的三个属性：**类型、名称、值**。

> [!info] Agent 补充
> 原始笔记中的"变量有萨格重要属性"应为"变量有**三个**重要属性：类型、名称、值"。名称用于在代码里引用它，类型决定解释方式，值是该空间当前的内容。
> 常见基本类型：`int`（整数）、`double`（双精度浮点）、`char`（字符）、`bool`（布尔）。需要精确宽度时用 `<cstdint>` 中的 `int32_t` / `uint64_t` 等固定宽度类型。

## 2. 变量的定义与命名

- **定义格式**：
  ```
  类型名 变量名1, 变量名2, ..., 变量名n;
  ```
  例如 `int a, b, c;` 一次定义三个 `int` 变量。
- **标识符（identifier）命名规则**：
  1. 必须以字母或下划线 `_` 开头；
  2. 其余字符必须是数字、字母或下划线，不能使用空格或其他特殊符号；
  3. 不能是系统的关键字 / 保留字（如 `int`、`return`、`class`）；
  4. C++ 标准没有规定名字长度上限，但各编译器有自己的限制；
  5. **区分大小写**：`count` 与 `Count` 是两个不同的名字；
  6. 名字应能让读者明白其含义（可读性优先）。

> [!warning] 常见陷阱
> - 以双下划线 `__` 或"下划线 + 大写字母"开头的名字保留给编译器 / 标准库实现，不要自己使用；
> - 命名风格保持一致（如 `snake_case` 或 `camelCase`），同一项目内不要混用。

## 3. 变量初始化

> [!note] 我的原始理解（未验证）
> - `int num2(2)` 直接初始化
> - `int num3 = {3}` 列表初始化
> - 定义的位置：函数体的开始处集中定义；使用前，防止定义未使用

- 常见初始化写法：
  ```cpp
  int a = 2;    // 拷贝初始化
  int b(2);     // 直接初始化
  int c{2};     // 列表初始化（C++11，推荐）
  int d = {2};  // 拷贝列表初始化
  int e{};      // 值初始化：e 被初始化为 0
  ```
- **列表初始化的优点**：禁止"窄化转换"（如 `int x{1.5}` 会编译报错），更安全，现代 C++ 推荐优先使用；
- **定义的位置**：不必集中在函数体开头；提倡**在使用处附近定义并初始化**，减少"定义了却没用到"，也避免忘记初始化。

> [!info] Agent 补充（纠正原始笔记）
> 原始笔记把 `int num3 = {3}` 统称为列表初始化；严格说它是**拷贝列表初始化**，`int num3{3}` 才是直接列表初始化（两者对内置类型效果相同）。
> 另一条硬建议：**定义变量时尽量同时初始化**——未初始化的内置类型局部变量值不确定，读取它是常见的未定义行为来源。

## 4. 整型数的机器表示：原码 / 反码 / 补码

> [!note] 我的原始理解（未验证）
> 数字的三种编码方式为：源码、反码、补码
> - 原码就是符号位加上真值的绝对值
> - 反码：为了解决原码无法执行减法运算的问题
> - 补码：现代计算机使用的编码格式，解决了反码的缺点

以 8 位为例：

| 码制 | 正数 | 负数 | 特点 |
| --- | --- | --- | --- |
| 原码 | 符号位 0 + 绝对值 | 符号位 1 + 绝对值 | 有 +0 / −0 两种零，减法不便 |
| 反码 | 与原码相同 | 符号位不变，其余按位取反 | 仍有 ±0，运算需循环进位 |
| 补码 | 与原码相同 | 反码 + 1 | 只有一个 0，加减法统一，现代计算机采用 |

- 例（8 位）：$+5$ 的原码 / 反码 / 补码都是 `0000 0101`；$-5$ 原码 `1000 0101`、反码 `1111 1010`、补码 `1111 1011`；
- **补码的直觉**：在模 $2^n$ 的意义下，$x$ 与 $x + 2^n$ 等价，于是"$-x$"可以用"$2^n - x$"表示，**减法就变成加法**；
- 这也解释了整型的取值范围：$n$ 位补码可表示 $-2^{n-1}$ 到 $2^{n-1}-1$（如 32 位 `int` 约为 $\pm 2\times 10^9$）。

> [!info] Agent 补充（纠正原始笔记）
> 原始笔记中的"源码"应为"**原码**"（sign-magnitude）。C++20 起，标准要求有符号整数采用补码表示；在此之前属于实现定义，但实践中几乎都是补码。

## 5. 枚举类型 enum

> [!note] 我的原始理解（未验证）
> ```cpp
> enum Season {Spring, Summer, Autumn, Winter};
> Season mySeason = Spring;
> ```

- **枚举（enumeration）**：把一组有名字的整型常量组织成一个类型，提高可读性、避免"魔法数字"：
  ```cpp
  enum Season { Spring, Summer, Autumn, Winter };
  Season s = Spring;          // 未限定作用域枚举：名字直接暴露在外层
  ```
- 默认取值从 0 开始依次 +1（`Spring = 0, Summer = 1, ...`），也可以显式指定：
  ```cpp
  enum Color { Red = 1, Green = 2, Blue = 4 };
  ```
- **C++11 起推荐"枚举类"**（scoped enumeration）：名字不泄漏到外层作用域，且不会隐式转换为 `int`：
  ```cpp
  enum class Season { Spring, Summer, Autumn, Winter };
  Season s = Season::Spring;  // 必须用 Season:: 限定
  // int x = s;               // 错误：不会隐式转换，更安全
  ```

> [!warning] 常见陷阱
> 未限定作用域枚举的枚举名会进入外层作用域，容易与其他名字冲突；能用 `enum class` 就优先用。

## 常见误解

1. **"变量只是一个名字"** → 错。它对应内存中的一块存储空间，有大小、布局与生命周期。
2. **"类型只影响取值范围"** → 不全。类型还决定内存大小、布局与能参与的运算。
3. **"不初始化也能用"** → 危险。内置类型的局部变量不初始化时值不确定，读取属于未定义行为。
4. **"`int c{1.5}` 会自动截断"** → 错。列表初始化禁止窄化转换，会直接编译报错。
5. **"原码就是计算机使用的编码"** → 错。现代计算机使用**补码**。

## 应用

- 理解类型与内存布局，是后面学指针、引用、`sizeof`、对象生命周期的基础（Level 4）；
- 补码解释了整型溢出与位运算的行为（Level 4 / 位操作）；
- `enum class` 是工程中表达状态机、选项、错误码的常用手段（Level 3 / 9）。
