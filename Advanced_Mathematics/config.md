# config.md — 知识库规范

> 本文件是整个高等数学知识库的**规范权威来源**：长期目标与写作规范都定义在这里。
>
> **适用范围**：`Advanced_Mathematics/` 下所有 Markdown 文件（现有及以后新增）。
> **维护原则**：维护知识库时（新建笔记、练习、资源条目、回答学习问题）默认遵守本文件；如内容有冲突，以本文件为准。

## 1. 学习者背景

- 目标读者：面向人工智能 / 计算机方向的本科生，按此标准学习和写作；
- 数学起点：**高中数学已扎实**（函数、三角、解析几何、基础代数），不复习、不铺垫高中内容；本库 Level 0 只做"函数与映射"的系统化收口，然后直接进入极限与微积分；
- 学习心态：不是应试导向，接受"先直觉、后严格"的路径；
- 使用环境：Obsidian 笔记库 + Markdown，笔记要可复读、可检索、可持续迭代。

## 2. 学习目标

1. **理解变化与累积**：极限、导数、积分分别回答"趋近什么""变化多快""累积多少"；
2. **建立知识体系**：把函数 → 极限 → 导数 → 积分 → 多元微积分串成一条线，并与线性代数互相引用；
3. **学以致用**：每个核心概念都能说出它在 ML / 优化 / 数值计算中的真实用途；
4. **可维护**：用自己的话重组，标注来源与日期，允许半年后回看仍然读得懂。

**单个 Level 的完成标准**：

- 能用一两句话讲清该 Level 的核心概念与几何意义；
- 能独立完成配套练习（含必要的推导）；
- 能在 AI / 工程场景中找到至少一个真实例子并写进笔记。

## 3. 笔记格式要求

**通用规范**

- 使用 Markdown，中文为主；术语首次出现时保留英文原名（如 导数 derivative、极限 limit）；
- 一主题一文件，文件名清晰，按 Level 组织，例如 `Notes/Level2_Derivatives_and_Differentials.md`；
- 公式用 Obsidian 原生 LaTeX：行内 `$...$`，独立公式 `$$...$$`；公式要有文字解释，不堆公式；
- 每篇笔记记录日期与来源（教材 / 课程 / 视频 + 章节），便于回溯；
- 禁止大段照抄教材，必须用自己的话重组；
- 疑问用 `> [!question] 未解决` 标记，不积压在正文里。

**笔记模板**

```markdown
# 主题名

## 直觉
（为什么学、几何 / 物理意义、一句话解释）

## 定义
（严谨定义 + 自己的话复述）

## 关键公式与结论
（公式 + 符号含义 + 具体小例子）

## 常见误解
（"错误 → 正确"对照）

## AI / 工程应用
（梯度下降、损失函数、数值方法等真实场景）

## 遗留疑问
（用 `> [!question] 未解决` 标记，纳入 MOC 汇总）
```

## 4. 内容类型标记（必须区分）

| 类型 | 含义 | 写法 |
| --- | --- | --- |
| 我的原始理解 | 用户自己的话，可能对可能错 | `> [!note] 我的原始理解（未验证）` + 原文 |
| 已验证知识 | 有来源 / 推导，可作为事实 | 正式正文，标注来源与日期 |
| 未解决问题 | 尚未解答的疑问 | `> [!question] 未解决：...`（笔记内标记，MOC 汇总） |
| Agent 补充内容 | Agent 查资料 / 推导补充的 | `> [!info] Agent 补充：` 明确标注并注明来源 |

**硬规则**：用户的猜测不能直接作为事实写入正文，只能保留为"我的原始理解（未验证）"，或验证后升级。

## 5. 与线性代数的分工

| 知识库 | 负责 | 典型内容 |
| --- | --- | --- |
| `Advanced_Mathematics/`（本库） | 变化与累积 | 函数、极限、导数、积分、多元微积分 |
| `Linear_Algebra/` | 结构与变换 | 向量、矩阵、线性方程组、空间、特征值、SVD |

跨库引用使用 Wiki Links；函数与映射的**基础视角**在 `Linear_Algebra/Notes/Level0_Mathematical_Foundation.md` 也有简述，更深内容以本库为准，避免重复展开。

## 6. 修改文件的原则

- **增量修改**：不删除正确内容、不无理由重写、不改变已有知识结构；
- 重命名 / 移动文件前，先检查并更新所有引用它的 Wiki Links；
- 修改 config.md 等规范文件属于重大变更：先说明理由，再同步更新 README 与相关模板。

## 7. Obsidian Vault 维护规范

- **Wiki Links**：已有内容直接引用，不重复建立；不为建链接而创建大量空白文件；
- **YAML Frontmatter**：主要笔记使用 `title / type / subject / level / tags`，tags 精简；
- **Callout**：适度使用 `> [!note]` / `> [!tip]` / `> [!example]` / `> [!warning]` / `> [!abstract]`；
- **MOC**：维护 `00 - MOC/Advanced Mathematics MOC.md`，随学习进度更新，并汇总"未解决问题"；
- **文件粒度**：一个 Level 对应一个主要 Markdown 文件；只有被大量引用的独立概念（如梯度、泰勒公式、微积分基本定理）才单独建笔记；
- **Inbox 工作流**：原始笔记 → Agent 整理 → 正式笔记 → 原文件移入 `Inbox/Processed/`（永不删除），详见根目录 [[Knowledge_Workflow]]。
