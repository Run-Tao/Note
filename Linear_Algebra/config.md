# config.md — 知识库规范

> 本文件是整个线性代数知识库的**规范权威来源**：长期目标与写作规范都定义在这里。
>
> **适用范围**：`Linear_Algebra/` 下所有 Markdown 文件（现有及以后新增）。
> **维护原则**：维护知识库时（新建笔记、练习、应用笔记、资源条目、回答学习问题）默认遵守本文件；如内容有冲突，以本文件为准。

## 1. 学习者背景

- 目标读者：面向人工智能 / 计算机方向的本科生，按此标准学习和写作；
- 数学起点：具备高中数学基础（函数、三角、解析几何），线性代数从零开始，按 [Learning_Roadmap.md](Learning_Roadmap.md) 的 Level 0 补齐数学语言；
- 学习心态：不是应试导向，接受"先直觉、后严格"的路径——先理解为什么，再补严谨定义与计算；
- 使用环境：Obsidian 笔记库 + Markdown，笔记要可复读、可检索、可持续迭代。

## 2. 学习目标

1. **不只应付考试**：理解每个概念背后的几何直觉与数学思想，而不是只记住计算步骤；
2. **建立知识体系**：让概念之间互相连接（例如 SVD ↔ PCA ↔ 低秩近似），形成网络而不是孤点；
3. **学以致用**：每个核心概念都能说出它在 AI 中的至少一个真实应用；
4. **可维护**：笔记经过自己的话重组，标注来源与日期，允许半年后回看仍然读得懂。

**单个 Level 的完成标准**：

- 能用一两句话向别人讲清该 Level 的核心概念；
- 能独立完成配套练习（含 Python/NumPy 验证）；
- 能在 AI 应用中找到至少一个真实例子并写进笔记。

## 3. 面向方向

知识库的所有内容最终服务于以下四个方向的线性代数应用：

| 方向 | 典型主题 | 对应的线代工具示例 |
| --- | --- | --- |
| 机器学习（ML） | 回归、分类、聚类、降维、正则化 | 最小二乘、SVD、PCA、特征分解 |
| 深度学习（DL） | 神经网络、反向传播、优化、Transformer | 矩阵乘法、雅可比矩阵、谱范数、低秩近似 |
| 计算机视觉（CV） | 图像表示、卷积、特征图 | 矩阵/张量、卷积的矩阵形式 |
| 语音处理与 NLP | 信号处理、词嵌入、注意力、向量检索 | 复数与 FFT、内积、Q/K/V 投影 |

写作要求：每个概念尽量标注所属方向，形成"概念 → 应用"的双向关联；面向方向的分类存放于 [AI_Applications](../AI_Applications/README.md)。

## 4. 笔记格式要求

**通用规范**

- 使用 Markdown，中文为主；术语首次出现时保留英文原名（如 特征向量 eigenvector）；
- 一主题一文件，文件名简洁清晰，按 Level 组织，例如 `Notes/Level1_Vectors/向量点积.md`；
- 涉及公式时使用数学公式语法（Obsidian 支持 LaTeX）；公式要有文字解释，不能只堆公式；
- 每篇笔记记录日期与来源（教材/课程/视频/论文 + 链接），便于回溯；
- 禁止大段照抄教材或资料，必须用自己的话重组；
- 学习过程中产生的疑问在笔记中用 `> [!question] 未解决` 标记，不积压在笔记正文里。

**笔记模板**（每篇笔记按此结构组织）

```markdown
# 主题名

## 直觉
（为什么学、几何/物理意义、一句话解释）

## 定义
（严谨定义 + 自己的话复述）

## 关键公式
（公式 + 每个符号的含义 + 一个具体小例子）

## 常见误解
（学习时容易搞错的地方，用"错误 → 正确"对照写）

## AI 应用
（按第 5 节要求写）

## 遗留疑问
（用 `> [!question] 未解决` 标记，纳入 MOC 未解决问题汇总）
```

## 5. AI 应用要求

每个核心概念至少对应一个**真实的** AI 应用场景，遵循四问模板：

1. 解决什么问题？
2. 用到哪个线代工具 / 概念？
3. 为什么有效（背后的数学原因）？
4. 对应我学过的哪个概念？

**质量要求**

- 应用必须具体：写出模型名、具体环节或公式出处，禁止"PCA 用于降维"这类泛泛而谈；
- 按方向组织应用笔记（ML / DL / CV / NLP 与语音），存于 [AI_Applications](../AI_Applications/README.md)；
- 每个应用标注理解深度：**I**（仅了解直觉）/ **U**（理解原理）/ **D**（能推导或实现），如实标记，避免"看起来懂了"。

## 7. Obsidian Vault 维护规范（2026-08-13 增补）

本知识库同时是一个长期维护的 Obsidian Vault（位置 `D:\Run_Tao\Note\Linear_Algebra`）。除以上规范外，维护时默认遵守：

- **Obsidian 兼容**：使用标准 Markdown；公式用 Obsidian 原生 LaTeX——行内 `$...$`，独立公式 `$$...$$`；
- **YAML Frontmatter**：主要知识笔记使用 `title` / `type` / `subject` / `level` / `tags`；tags 只保留有意义的少量标签，不堆砌；
- **Wiki Links**：概念之间优先用 `[[...]]` 建立联系；已有内容直接引用，不重复建立；未存在的概念可以建立链接，但不为建链接而创建大量空白文件；
- **Callout**：适度使用 `> [!note]`、`> [!tip]`、`> [!example]`、`> [!warning]`、`> [!abstract]`，仅在确实有助于阅读时使用；
- **知识网络**：每个主要章节尽量说明前置知识、核心概念、后续知识、相关概念、AI 应用；
- **文件粒度**：一个 Level 对应一个主要 Markdown 文件；只有 SVD、PCA、Eigenvalues、Linear Transformation 这类独立价值高且会被大量引用的概念才建立独立笔记；
- **MOC**：维护总览页 `00 - MOC/Linear Algebra MOC.md`，展示完整学习路线与核心概念链接，随知识库发展更新；
- **命名**：文件名清晰、稳定、一致；重命名前先检查并更新所有 Wiki Links；
- **修改原则**：增量修改——不删除正确内容、不无理由重写、不破坏链接、不改变已有知识结构；数学错误可修正但保留结构；
- **内容优先级**：为什么 → 直觉 → 定义 → 推导 → 计算 → 应用，不写成公式堆积；
- **AI 联系**：与 ML / DL / CV / 语音 / 数据表示适当联系；需要后续知识才能解释的，标注"将在后续章节讨论"，不提前展开；
- **Token 控制**：优先完成文件修改而非长篇聊天解释；不重复输出已存在的内容。

## 8. 知识库功能与核心工作流（2026-08-13 增补）

- **MOC**：`00 - MOC/Linear Algebra MOC.md` 展示学习路线、核心概念与知识关系；随学习进度逐步更新，不一次性填充全部内容；
- **未解决问题**：不设独立目录；疑问用笔记内 `> [!question] 未解决` callout 标记（问题 + 涉及概念 + 我的尝试 + 状态），由 MOC 的"未解决问题"汇总统一跟踪；解决后把答案沉淀回对应知识笔记并移除标记；
- **Exercises**：管理习题、典型题与错题；重点是记录错误原因和错误理解，而不是单纯保存大量题目；
- **Projects**：将数学知识与 Python 实验、AI 项目联系起来：数学概念 → Python 实验 → 可视化 / 实际应用 → 项目记录；
- **AI Applications**：单独记录数学知识在 ML / DL / CV / 语音处理中的实际应用；不为了关联 AI 而强行扩展；
- **Learning Log**：统一使用个人层 `00 - Personal/Learning Log/`（每周一篇 + 月复盘），本库不设独立学习日志目录；
- **Glossary**：术语表是单文件 `Glossary.md`，维护重要数学术语的中英文对应，并链接相关笔记；随学习进度增量补充；
- **文件管理**：遵循第 7 节文件粒度原则——不一次性创建大量文件，优先使用现有 Level 笔记，只有独立学习价值高且会被多次引用的概念才建立独立笔记；
- **核心工作流**：网页版 AI（概念学习、深入讨论、解决问题）→ Obsidian（沉淀理解、建立知识网络）→ Agent（整理文件、维护链接、更新 MOC、管理知识库）→ Python / Projects（实践和验证）。
